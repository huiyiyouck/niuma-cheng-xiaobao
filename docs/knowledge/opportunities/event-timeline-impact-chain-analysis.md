## 内容摘要

平台后续可以在“单条信息聚合和评分”之上，增加面向事件的时间线与影响链分析能力。

目标不是只展示孤立新闻，而是识别一个源头事件如何随时间发酵，并关联其对不同领域、行业或模块的后续影响。

示例：

```text
09:00 某公司发布最新模型
  → AI / 模型动态：模型能力变化
  → AI / 模型架构：相关技术讨论和方案变化
  → 财经 / 公司资讯：公司股价或相关板块波动
  → 行业动态：竞品回应、生态变化、市场预期变化
```

用户可以沿着时间线快速理解：

1. 最初发生了什么。
2. 哪些后续新闻属于同一事件的发酵。
3. 影响传播到了哪些空间和频道。
4. 不同领域变化之间可能存在什么关联。
5. 哪些事件具有可复用的影响模式，可用于后续判断和学习。

## 适用场景

- 追踪重大模型发布、公司公告、政策变化或市场事件的后续发酵。
- 将多个空间和频道中的相关新闻聚合为一个事件视图。
- 回顾“源头事件 → 行业变化 → 市场反馈”的传播链路。
- 为未来的趋势判断、影响预测和模式学习提供结构化样本。

## 不适用场景

- 不替代单条新闻的抓取、去重、摘要和评分。
- 不在 v0.5 信息源管理重构中实现。
- 初期不直接声称因果关系；应区分“时间相关”“内容相关”和“经验证的因果关系”。
- 初期不自动给出投资或业务决策结论。

## 初步产品形态

可以考虑两种互补视图：

1. **事件时间线**：按时间排序展示源头事件及后续相关新闻。
2. **影响链**：按空间和频道展示事件向不同领域扩散的路径。

初步命名候选：

- 事件时间线
- 新闻发酵链
- 事件影响链

其中“事件时间线与影响链分析”更适合作为内部能力名称；页面文案可以后续由 UI 和 PM 再确认。

## 与现有规划的关系

该能力依赖以下基础：

1. 信息源管理稳定，能够明确新闻来自哪个 Source。
2. 空间和频道结构稳定，能够描述新闻展示位置。
3. 单条新闻评分方法建立，能够筛出值得展开分析的事件。
4. 后续补充事件聚类、实体识别、时间关联和跨频道关联能力。

v0.5 仅需要确保信息源管理重构不阻断未来扩展，不新增事件时间线相关实现。
