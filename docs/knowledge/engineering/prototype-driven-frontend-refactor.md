# 原型驱动前端重构：1:1 还原 + mock 先行 + 后端渐进对接

## 元信息
- 类型：Engineering（工程实践）
- 来源：v0.6 Figma 原型前端重构实施路径（2026-06-13~06-28）
- 创建日期：2026-07-04
- 相关角色：Developer / PM / UI
- 相关迭代：v0.6（Figma 原型前端重构 + Tailwind v4 + shadcn 主题）

## 内容摘要

当有高保真 Figma 原型（React 技术栈）且前端需用不同技术栈（Vue）还原时，采用**原型驱动重构策略**：

### 三阶段实施路径

**阶段 1：底座 + 静态还原（mock 数据）**
- 先搭建技术栈底座：Vite 插件、主题 CSS、工具函数（cn/clsx/tailwind-merge）、图标库
- 按原型 1:1 还原页面和组件，所有数据用 mock
- 路由、布局、导航、抽屉/对话框等交互壳先做完
- 每完成一页 `npm run build` 验证，截图自查

**阶段 2：后端契约对接**
- 静态 UI 完成后，按页面优先级逐个接真实 API
- TS 类型与后端响应 1:1 对齐（camelCase）
- 加载态、错误态、空状态补全
- 旧路由兼容跳转（如合并页面时）

**阶段 3：交互精修 + 体验优化**
- 乐观更新（管理类操作）
- 状态色、Toast 反馈、统一 Loading
- 视觉细节精修（背景分层、字体层级、卡片阴影）
- 性能优化（动态 import、列表渲染）

### 关键原则

1. **原型优先**：Owner 明确「原型为主」时，UI spec 中与原型冲突的以原型为准
2. **技术栈选择从原型出发**：原型基于 shadcn/Tailwind 时，前端也引入对应体系，减少 className 转译成本
3. **前端先行**：先搭 UI 再做后端，避免后端契约反复返工
4. **渐进式接后端**：一页一页接，不一次性全量替换 mock
5. **构建即验证**：每完成一个模块 `npm run build` 确保 0 TS 错误

## 适用场景

- 有高保真 Figma/React 原型，需要用另一框架（Vue）落地
- 产品交互复杂，先确认 UI 再做后端效率更高
- 团队人力有限，前端和后端可以错峰进行
- 原型迭代快，后端契约容易变动

## 不适用场景

- 无原型或原型粗糙，无法作为 1:1 还原依据
- 后端契约已稳定且复杂，前端等待后端会浪费时间
- 纯后端功能，前端只有简单展示
- 团队有充足人力，可以前后端并行且联调成本低
