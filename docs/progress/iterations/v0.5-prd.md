## 1. 迭代目标

v0.5 将信息源从“某个空间中的附属配置”升级为可复用的全局资产，并让 X/Twitter 指定账号进入实时监听模式。

| 板块 | 目标 |
|------|------|
| A. 信息源管理重构 | 建立独立信息源库；固定空间 → 频道两级结构；支持 Source 标签、验证、运行状态、使用统计和多位置投放。 |
| B. 共享抓取与分发 | 同一个 Source 全局只抓取或监听一次，再向全部启用展示位置分发；全部位置停用后自动停止抓取。 |
| C. X/Twitter 实时监听 | 所有启用 X Source 共用一个 Filtered Stream 长连接，自动同步规则、自动重连，并保留 Source 级补偿抓取。 |
| D. 异常与告警 | 建立 Source 待修复、来源异常和自动恢复流程；增加顶级告警入口；区分 X Stream 全局异常。 |
| E. 业务数据重置 | 清空现有业务数据，不做旧业务数据迁移，不保留旧 API 兼容，以空白状态启动新模型。 |
| F. 评分方法论 | 交付一份可 Review 的信息评分方法论草稿，不落地评分代码。 |

## 2. 核心概念

### 2.1 空间与频道

内容组织固定为两级：

```text
空间
└── 频道
```

- 没有子频道。
- 不允许继续向下嵌套。
- 页面使用两层 Tab，不使用树形目录。
- `全部` 是聚合入口，不是真实频道。

### 2.2 信息源 Source

Source 是平台统一管理的外部内容来源，例如：

```text
OpenAI 官方 X：@OpenAI
OpenAI Blog RSS：https://example.com/rss.xml
```

Source 负责维护来源身份、标签、抓取策略、验证状态、抓取状态、异常信息和使用统计。

### 2.3 展示位置

展示位置表示 Source 获取的数据应该出现在哪里。

展示位置可以是：

```text
空间根节点
或
空间下的具体频道
```

一个 Source 可以拥有多个展示位置。同一个空间中，也允许同时投放到空间根节点和多个频道。

页面不展示技术术语 `Binding`，统一使用：

```text
展示位置
添加到空间
添加到频道
暂停接收
恢复接收
从当前位置移除
```

## 3. 用户故事

### 3.1 信息源资产化

**US-3.1.1** 作为平台管理员，我希望在独立的信息源库中统一维护 X/Twitter 和 RSS 来源，以便信息源不再附属于某一个空间。

**US-3.1.2** 作为平台管理员，我希望为信息源记录领域、来源角色、主题、关注级别和备注，以便沉淀我手工筛选来源时掌握的先验信息。

**US-3.1.3** 作为平台管理员，我希望将同一个信息源投放到多个空间或频道，以便一次抓取后满足多个内容组织场景。

**US-3.1.4** 作为平台管理员，我希望查看信息源被哪些空间和频道使用，以及哪些位置仍在启用，以便理解 Source 为什么仍然持续抓取。

### 3.2 空间与频道

**US-3.2.1** 作为平台管理员，我希望使用“空间 Tab + 频道 Tab”管理内容结构，以便直观切换 AI、财经等空间及其频道。

**US-3.2.2** 作为平台管理员，我希望频道可以创建、重命名、排序和删除，以便逐步调整内容组织。

**US-3.2.3** 作为平台管理员，我希望删除频道或空间时明确看到影响范围，并保留已有历史新闻，以免误删已沉淀内容。

### 3.3 Source 创建、验证与运行

**US-3.3.1** 作为平台管理员，我希望从信息源库或空间管理页创建 Source，并在保存前验证来源，以便尽早发现配置错误。

**US-3.3.2** 作为平台管理员，我希望验证失败的 Source 可以保存为待修复，但不能投放到空间或频道，以便保留收集线索而不启动错误抓取。

**US-3.3.3** 作为平台管理员，我希望来源异常时可以修改身份并重新验证，以便处理 RSS URL 失效或 X 账号改名。

**US-3.3.4** 作为平台管理员，我希望 Source 在至少一个位置启用时自动抓取，在所有位置暂停或移除后自动停止，以便避免重复配置和无效消耗。

### 3.4 X/Twitter 实时监听

**US-3.4.1** 作为平台管理员，我希望添加 X 账号后自动实时监听原创推文和引用推文，以便尽快获得新信息。

**US-3.4.2** 作为平台管理员，我希望所有账号共享一个长连接，以便满足 X API 连接限制并控制运行成本。

**US-3.4.3** 作为平台管理员，我希望 Stream 断线或服务重启后自动恢复，并通过低频 timeline 补偿抓取覆盖遗漏内容。

### 3.5 告警

**US-3.5.1** 作为平台管理员，我希望在顶级导航看到未处理告警数量，并进入统一告警页查看问题。

**US-3.5.2** 作为平台管理员，我希望单个 Source 异常和 X Stream 全局异常被区分记录，以免同一根因制造大量重复告警。

### 3.6 数据重置

**US-3.6.1** 作为平台 Owner，我希望上线新模型时清空当前没有保留价值的旧业务数据，以便从空白状态重新录入，不承担旧模型兼容成本。

### 3.7 评分方法论

## 4. 功能需求

### 4.1 页面信息架构

顶级导航：

```text
浏览 | 管理 | 系统日志 | 告警
```

管理页内部：

```text
空间管理 | 信息源库
```

空间管理使用两层 Tab：

```text
空间：
[ AI ] [ 财经 ]

频道：
[ 全部 ] [ 模型动态 ] [ 行业资讯 ] [ 开源项目 ]
```

行为：

- 浏览页选择 `全部` 时，聚合空间根节点和全部频道新闻，并自动去重。
- 浏览页选择具体频道时，只展示该频道新闻。
- 管理页选择 `全部` 时，只管理直接投放到空间根节点的 Source。
- 管理页选择具体频道时，只管理投放到该频道的 Source。
- 空间允许暂时没有频道。
- 同一空间内频道名称唯一，不同空间可以重名。
- 频道支持手动排序。

### 4.2 信息源库

信息源库使用表格为主视图，默认展示全部 Source，包括未使用和待修复状态。

建议列：

| 信息源 | 类型 | 标签 | 运行状态 | 使用位置 | 最近抓取 | 历史新闻 | 操作 |
|--------|------|------|----------|----------|----------|----------|------|

搜索范围：

```text
展示名称
来源身份
内容主题
备注
```

筛选项：

```text
类型
运行状态
领域标签
来源角色
关注级别
使用空间
```

Source 详情使用独立详情页或右侧详情抽屉，由 UI（界面设计师）在 UI 方案阶段确定。

详情至少展示：

- 基本资料。
- 标签和备注。
- 抓取状态和最近异常。
- 连续失败次数。
- 历史新闻数量。
- 展示位置总数、启用数量、暂停数量、涉及空间数量。
- 每个具体展示位置的空间、频道、状态和操作。
- 来源身份变更历史。

### 4.3 Source 标签

| 字段 | 是否必填 | 形式 | 首版值或示例 |
|------|----------|------|--------------|
| 类型 | 是 | 单选 | X/Twitter、RSS |
| 来源身份 | 是 | 文本 | @OpenAI、RSS URL |
| 展示名称 | 是 | 文本 | OpenAI 官方 X |
| 领域标签 | 是 | 固定选项，多选 | AI、财经、开源、科技、其他 |
| 来源角色 | 是 | 固定选项，单选 | 官方、媒体、KOL、社区、论文机构、其他 |
| 内容主题 | 否 | 自由标签，多选 | 模型发布、研究动态 |
| 关注级别 | 是 | 固定选项，单选 | 核心、常规、观察 |
| 备注 | 否 | 文本 | 重大产品发布优先关注 |

标签用于信息源库展示、搜索和筛选，并作为未来评分上下文。

v0.5 中标签不影响：

- 抓取频率。
- 抓取优先级。
- 入库规则。
- LLM 调用顺序。
- 单条新闻评分。
- 新闻状态流转。
- 自动推送。

### 4.4 Source 创建与验证

创建入口：

```text
信息源库 → 新建信息源
空间管理 → 添加信息源 → 搜索无结果 → 新建信息源
```

X/Twitter：

- 一个 Source 对应一个账号。
- 用户名不区分大小写，不区分是否带 `@`。
- 验证时展示账号名称、用户名和简介预览。

RSS：

- 一条 Feed 对应一个 Source。
- 一个网站存在多个 Feed 时，分别创建多个 Source。
- 验证时展示站点信息和最近文章预览。

重复检查：

| 类型 | 去重依据 |
|------|----------|
| X/Twitter | 标准化用户名 |
| RSS | 标准化 Feed URL |

验证失败：

- 可以保存为 `待修复`。
- 不允许添加到空间或频道。
- 不开始抓取。

来源身份修改：

- 正常状态和未使用状态下不允许直接修改来源身份。
- `待修复` 和 `来源异常` 状态允许修改身份。
- 修改后必须重新检查重复来源并重新验证。
- 验证成功后才恢复可用。
- 保留来源身份变更历史。

### 4.5 展示位置与共享分发

规则：

- Source 可以直接投放到空间根节点。
- Source 可以投放到一个或多个频道。
- 同一 Source 可以投放到多个空间。
- 同一 Source 可以投放到同一空间的多个频道。
- 展示位置可以独立暂停或恢复。
- 内容只保存一份，再关联到多个展示位置。
- 空间聚合视图自动去重。

Source 是否抓取由系统自动判断：

```text
至少存在一个启用展示位置
→ Source 抓取中

全部展示位置暂停或移除
→ Source 已停止
```

抓取配置属于 Source：

| 配置项 | 说明 |
|--------|------|
| RSS 抓取周期 | Source 全局配置 |
| X 补偿抓取周期 | Source 全局配置，默认 24 小时 |
| 单次最大抓取条数 | Source 全局配置 |

### 4.6 Source 状态

| 状态 | 含义 |
|------|------|
| 正常 | 验证通过，可以投放 |
| 待修复 | 创建时验证失败，不允许投放 |
| 抓取中 | 至少一个展示位置启用 |
| 已停止 | 没有启用展示位置 |
| 来源异常 | 曾经正常，但后续持续失败 |
| 来源已移除 | Source 已删除，仅供历史新闻展示 |

连续失败达到 `3` 次后，Source 标记为来源异常并生成告警。

异常处理：

| 异常类型 | 处理 |
|----------|------|
| 临时网络错误、5xx | 指数退避重试 |
| 429 限流 | 按服务端提示或指数退避 |
| RSS 404、X 账号失效 | 暂停 Source，等待修复 |
| 401、403 鉴权失败 | 生成高优先级告警 |
| 单条内容解析失败 | 跳过当前内容，继续后续处理 |
| 系统内部错误 | 生成系统告警，不直接归因于 Source |

临时异常恢复成功后，Source 自动恢复，关联告警标记为已恢复。

### 4.7 X/Twitter 共享 Stream

所有启用中的 X Source 共用一个 Filtered Stream 长连接。

```text
一个共享长连接
├── @OpenAI：存在启用位置 → 保留规则
├── @AnthropicAI：存在启用位置 → 保留规则
└── @Example：没有启用位置 → 不创建规则
```

规则：

- 一个 X Source 对应一个账号。
- 一个启用账号对应一条 `from:{username} -is:retweet -is:reply` 规则。
- 收录原创推文和引用推文。
- 不收录回复和转推。
- 首次启用展示位置时新增规则。
- 新增第二个展示位置时不新增重复规则。
- 暂停最后一个启用位置时移除规则。
- 恢复任意位置时恢复规则。
- 规则变化在 `30` 秒内自动同步。
- 服务重启后自动同步规则并恢复 Stream。
- 网络断开后指数退避重连。
- Stream 与 timeline 补偿抓取复用同一去重逻辑。

X Stream 全局异常：

- Bearer Token 失效、共享连接持续断开或规则同步失败时，生成一条 X Stream 全局告警。
- 不为每个 X Source 重复生成同一根因告警。

### 4.8 告警

顶级导航增加告警入口，并展示未处理数量。

告警状态：

```text
未处理
已确认
已恢复
已忽略
```

告警页至少覆盖：

- Source 来源异常。
- X Stream 全局异常。
- X API 鉴权失败。
- 系统级数据库或任务队列异常。

### 4.9 删除

删除 Source：

- 删除 Source。
- 删除全部展示位置。
- 停止抓取。
- 保留历史新闻。
- 历史新闻标记“来源已移除”。
- 删除前展示影响范围，并要求输入 Source 名称确认。

删除频道：

- 不删除 Source。
- 不删除历史新闻。
- 允许选择将展示位置迁移到空间根节点，或直接移除展示位置。
- 保留历史展示位置快照。

删除空间：

- 删除空间下的频道和展示位置。
- 不删除全局 Source。
- 不删除历史新闻。
- 不影响 Source 在其他空间中的展示位置。
- 保留历史展示位置快照。
- 删除前展示影响范围，并要求输入空间名称确认。

### 4.10 业务数据重置

Owner 已确认旧业务数据没有保留价值。

上线新模型时清空：

```text
旧空间
旧频道或 sub_channels
旧 Source
旧展示位置
旧原始抓取记录
旧任务
旧新闻
旧告警
```

保留：

```text
数据库 Schema
数据库迁移机制
系统配置
环境变量
```

运行日志是否保留，由 DevOps（运维/部署工程师）根据排障价值评估。

执行要求：

- 不做旧业务数据迁移。
- 不保留旧 API 兼容逻辑。
- 清理脚本进入 Git 管理。
- Architect Review 表级范围和依赖顺序。
- DevOps 执行前输出表级数据量统计。
- Owner 确认统计结果后，才允许执行生产环境清理。
- Tester 验证清理后系统可以从空白状态完成首个空间、频道、Source 和展示位置创建流程。

### 4.11 评分方法论文档交付

本迭代交付：

```text
docs/progress/ad-hoc/2026-06-02-product-brief-scoring-methodology.md
```

方法论确认：

- 评分对象是单条信息。
- 候选维度为时效性、影响力、置信度、行动性、独特性。
- 首版启用时效性、影响力、置信度。
- 每个首版维度使用 `1-5` 整数分，并输出一句简短理由。
- LLM 只输出维度分，不输出场景分、推送、日报或分流建议。
- 空间必须选择基础权重版本。
- 频道默认继承空间权重，也允许覆盖。
- 权重方案和权重版本分层。
- 权重版本状态为草稿、可用、已弃用、已归档。
- 已弃用版本不允许新增使用，但已有位置继续生效。
- 评分记录和场景分记录不覆盖历史。
- Source 关注级别暂不参与计算。

本迭代不实现评分代码，不讨论评分结果分流。

## 5. 验收标准

### 5.1 空间与频道

- **AC-5.1.1** 当用户进入浏览页或空间管理页时，应该看到空间 Tab 和当前空间的频道 Tab，不应该看到“子频道”文案或多级树形目录。
- **AC-5.1.2** 当用户创建空间但不创建频道时，应该可以将 Source 直接添加到空间根节点。
- **AC-5.1.3** 当用户在同一空间创建重名频道时，系统应该阻止保存；不同空间允许存在同名频道。
- **AC-5.1.4** 当用户调整频道顺序并重新进入页面时，应该看到调整后的顺序。
- **AC-5.1.5** 当用户浏览空间的 `全部` Tab 时，应该看到空间根节点和全部频道新闻的聚合结果；同一条新闻只展示一次。
- **AC-5.1.6** 当用户浏览具体频道时，应该只看到投放到该频道的新闻。

### 5.2 信息源库

- **AC-5.2.1** 当用户进入信息源库时，应该看到全部 Source，包括未使用和待修复来源。
- **AC-5.2.2** 当用户使用名称、来源身份、内容主题或备注搜索时，应该返回匹配 Source。
- **AC-5.2.3** 当用户按类型、运行状态、领域标签、来源角色、关注级别或使用空间筛选时，应该返回匹配 Source。
- **AC-5.2.4** 当用户查看 Source 详情时，应该看到运行状态、最近抓取、最近异常、连续失败次数、历史新闻数、使用位置统计和具体空间/频道。
- **AC-5.2.5** 当用户编辑 Source 的展示名称、标签、关注级别或备注时，系统应该保存新值。

### 5.3 创建与验证

- **AC-5.3.1** 当用户创建 X Source 时，应该只能录入一个账号；`@OpenAI`、`openai` 和 `@openai` 应被识别为同一来源。
- **AC-5.3.2** 当用户创建 RSS Source 时，一条 Feed URL 应该对应一个 Source；重复 URL 应被识别并阻止重复创建。
- **AC-5.3.3** 当验证通过时，Source 应该可以被添加到空间或频道。
- **AC-5.3.4** 当验证失败时，用户应该可以将 Source 保存为待修复，但不能添加到空间或频道，系统也不能开始抓取。
- **AC-5.3.5** 当待修复或来源异常 Source 修改身份时，系统应该重新检查重复来源并重新验证；成功后才恢复可用。
- **AC-5.3.6** 当正常或未使用 Source 尝试直接修改来源身份时，系统应该阻止修改。

### 5.4 多位置投放与共享抓取

- **AC-5.4.1** 当同一个 Source 被添加到多个空间或频道时，系统应该只抓取一次，只处理一次，并将同一份新闻关联到所有启用位置。
- **AC-5.4.2** 当某个展示位置暂停时，该位置不应该接收后续新内容；其他启用位置不受影响。
- **AC-5.4.3** 当 Source 仍有至少一个启用位置时，系统应该继续抓取。
- **AC-5.4.4** 当 Source 全部展示位置暂停或移除时，系统应该停止抓取。
- **AC-5.4.5** 当用户查看 Source 详情时，应该看到展示位置总数、启用数量、暂停数量和涉及空间数量。

### 5.5 X/Twitter 实时监听

- **AC-5.5.1** 当首个展示位置启用某个 X Source 时，后台应该在 `30` 秒内增加该账号规则，并通过共享 Stream 接收原创推文和引用推文。
- **AC-5.5.2** 当同一个 X Source 增加第二个展示位置时，后台不应该增加重复规则。
- **AC-5.5.3** 当最后一个启用位置暂停或移除时，后台应该在 `30` 秒内移除该账号规则。
- **AC-5.5.4** 当服务重启或 Stream 网络中断时，后台应该自动恢复规则和共享连接。
- **AC-5.5.5** 当 Stream 和 timeline 补偿抓取获得同一条推文时，系统应该只生成一份原始记录和一份新闻。
- **AC-5.5.6** 当账号发布回复或转推时，系统不应该将其收录；引用推文应该收录。
- **AC-5.5.7** 当用户新建 X Source 时，补偿抓取周期默认应该是 `24` 小时，并允许修改。

### 5.6 异常与告警

- **AC-5.6.1** 当 Source 连续失败不足 `3` 次时，系统应该记录日志并自动重试，不立即标记来源异常。
- **AC-5.6.2** 当 Source 连续失败达到 `3` 次时，系统应该标记来源异常并生成告警。
- **AC-5.6.3** 当临时异常后的抓取成功时，系统应该自动恢复 Source 状态，并将关联告警标记为已恢复。
- **AC-5.6.4** 当 RSS URL 失效或 X 账号失效时，系统应该暂停对应 Source，等待用户修复。
- **AC-5.6.5** 当 X Bearer Token 失效、共享连接持续断开或规则同步失败时，系统应该生成一条 X Stream 全局告警，不应该为每个 X Source 重复生成相同根因告警。
- **AC-5.6.6** 当用户进入任意页面时，顶级导航应该展示未处理告警数量；进入告警页后应该可以查看未处理、已确认、已恢复、已忽略状态。

### 5.7 删除

- **AC-5.7.1** 当用户删除 Source 时，系统应该展示受影响位置并要求输入 Source 名称确认；删除后停止抓取、移除全部展示位置，但保留历史新闻。
- **AC-5.7.2** 当历史新闻对应的 Source 已删除时，历史新闻仍应该可查看，并显示“来源已移除”。
- **AC-5.7.3** 当用户删除仍有展示位置的频道时，系统应该允许选择迁移到空间根节点或移除展示位置；Source 和历史新闻应该保留。
- **AC-5.7.4** 当用户删除空间时，系统应该展示影响范围并要求输入空间名称确认；删除后移除该空间的频道和展示位置，但保留 Source、历史新闻和历史位置快照。

### 5.8 数据重置

- **AC-5.8.1** 当 DevOps 准备执行生产数据清理时，应该先输出表级数据量统计，并等待 Owner 明确确认。
- **AC-5.8.2** 当数据清理执行完成时，旧空间、旧频道、旧 Source、旧展示位置、旧原始记录、旧任务、旧新闻和旧告警应该为空。
- **AC-5.8.3** 当清理后首次使用系统时，用户应该可以从空白状态创建空间、频道、Source 和展示位置，并开始抓取。
- **AC-5.8.4** 当上线新模型时，不应该保留旧 API 兼容逻辑。

### 5.9 评分方法论文档

- **AC-5.9.1** 当 Reviewer 阅读评分方法论文档时，应该可以明确区分评分目的、首版维度、预留维度和本轮不做事项。
- **AC-5.9.2** 当 Reviewer 阅读三个首版维度时，应该看到每个维度的 `1-5` 分锚点和 LLM 输出理由要求。
- **AC-5.9.3** 当 Reviewer 阅读场景分规则时，应该看到空间基础权重、频道继承或覆盖、权重之和为 `1` 和权重版本状态机。
- **AC-5.9.4** 当 Reviewer 阅读版本规则时，应该看到已弃用版本不允许新增使用但已有位置继续生效，使用位置归零后才能归档。
- **AC-5.9.5** 当 Reviewer 阅读范围边界时，不应该看到评分后分流、日报、推送或评分代码落地要求。

## 8. 风险和开放问题

| 风险或开放问题 | 影响 | 处理方式 |
|----------------|------|----------|
| X API 套餐、连接数、规则数或计费策略变化 | Stream 无法上线或成本超出预期 | DevOps 上线前再次核验当前 Developer Console |
| Source 资产化和多位置分发改变现有数据模型 | 前后端与 Worker 改动较大 | Architect 设计阶段明确数据模型和删除语义 |
| 旧数据全部清理不可恢复 | 误删仍有价值的数据 | DevOps 输出表级统计，Owner 确认后执行 |
| `sub_channels` 术语与新产品模型不一致 | 后续维护认知成本 | Architect 评估是否统一重构为 `channels` |
| 历史新闻保留但 Source 或位置已删除 | 历史详情难以解释 | 保留来源移除标记和历史位置快照 |
| 单实例 Stream Manager 不支持未来水平扩容 | 扩容时可能重复监听 | 本轮明确单实例边界，后续再增加选主机制 |
| 评分方法论尚未落地代码 | 本轮无法验证实际评分质量 | 本轮只完成方法论 Review，后续单独规划实现 |
| 置信度长期是否应进入场景分尚未确定 | 后续评分公式可能调整 | 用真实数据校准，评分与权重均做版本化 |
