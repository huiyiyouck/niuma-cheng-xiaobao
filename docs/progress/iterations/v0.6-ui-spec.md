### 1.3 关键任务流程

#### 浏览高价值新闻

1. 进入 `/news`，统计卡片显示今日 L1 completed 数 + 总 L1 completed 累计
2. 选择空间 Pill → 选择频道 Pill → 看新闻列表
3. 点击新闻卡片 → 右侧滑出 480px 抽屉
4. 抽屉展示 6 段：摘要 / 翻译 / 背景补全（含来源+可信度） / AI 分析 / 评分（默认折叠 4 维） / 5 类标签
5. 关闭抽屉：点蒙层 / 点 × / 按 ESC

#### 创建空间 + 上传图标

1. 进入 `/admin`，默认 Tab 「空间管理」
2. 点击「+ 新建空间」卡片 → 弹出 SpaceEditDialog
3. 输入空间名 + 描述
4. 图标区：可选填 emoji 或点击「⬆ 上传图片」上传 PNG/JPG ≤ 1MB
5. 保存 → Toast 提示创建成功 → 空间卡片显示
6. 双击空间卡片 → 同一弹窗回填数据 → 可编辑或替换/移除图标

#### 查看 L0/L1 处理状况

1. 进入 `/monitoring`，默认 Tab 「告警」
2. 切换到 Tab 「日志」可看抓取/Worker/Stream/API 日志
3. 进入 `/sources/:id`，左栏底部「最近一周新闻」时间轴下方新增「L0/L1 处理状态计数」区块
4. 区块显示：completed N / skipped N / retryable_failed N / final_failed N（四色徽章）
5. 点击 retryable_failed 数 → 跳转到 `/monitoring?tab=logs&source=:id&level=ERROR`

#### 三路径新增信息源

1. 路径 A：`/admin` 信息源库 Tab → 表格右上「+ 添加信息源」→ AddSourceDrawer
2. 路径 B：`/admin` 空间管理 Tab → 选中某频道 → 频道列表右上 「+ 添加 Source」→ AddSourceDrawer（预填空间+频道）
3. 路径 C：`/sources/:id` 右栏「展示位置」→ 「+ 添加位置」→ AddSourceDrawer（预填 Source ID）

> 三路径都打开同一个 AddSourceDrawer 组件，预填参数不同。这是 v0.6 新增的第三入口（C）。

## 9. 风险和遗留

### 9.1 已知风险

- **R1（中）**：原型 5 类标签只画 2 类、综合分阈值用 Tailwind 颜色名（不是 v0.5 CSS 变量），UI spec 已显式映射但 Developer 实现时仍需对照映射表，否则颜色会偏离设计。
- **R2（中）**：本期新增 12 个组件 + 6 个新 API endpoint，单纯 Developer 工程量约 v0.5 70% 体量；Tester 联调需要后端 mock 优先，spec 已假设契约可作 Tester 优先级排期参考。
- **R3（低）**：监控页角标数据源沿用 v0.5 alerts 表 unhandled 计数，本期不变；如设计阶段决定告警来源也包括 L0/L1 final_failed 自动告警（AC-32），需更新角标计数口径。
- **R4（低）**：抽屉 480px 在移动端转 100% 全宽，断点 768px（v0.5 通用断点）；如 Owner 主要在桌面使用，可推后移动端适配优先级。

### 9.2 设计阶段需要 Architect 确认的事项

1. NewsDetail 完整数据契约（§6.1）
2. SourceLevelStatusCounts API 是新建独立 endpoint 还是 `/v1/sources/:id` 内联返回
3. 图片上传 endpoint 路径、multipart 字段名、错误码规范
4. 旧 URL 兼容跳转放 Vue Router 内还是 nginx rewrite
5. 角标轮询频率是否提升（v0.5 是 60s，监控合并后是否需要更快）

### 9.3 实现阶段建议

- 新建 12 个组件可分两批：第一批 NewsDetailDrawer + 5 子组件（DrawerSummary/Translation/Context/Score/Tags + ConfidenceBadge + SourceTagRow），第二批 IconEditField/Uploader/SpaceIcon + SourceLevelStatusCounts + SourceRecentNewsTimeline + MonitoringPage/Tabs。
- 旧 `/alerts` `/logs` 路由的 redirect 必须保留至少一个版本，避免外链 / Owner 书签失效（AC-33 联动）。
- 五类标签的 `tags.domain[]` 等字段建议先按"空数组兼容"实现，AI 输出阶段性缺失不应阻塞 UI 渲染。

- 风险：如果所有页面都无上限铺满，新闻列表和管理区在宽屏上可能再次出现阅读动线过散、行长过长的问题，导致实现后返工。
- 建议：UI R2 明确「顶导全宽，内容区按页面设上限」或给出分页面规则。例如：NewsPage / AdminPage 主内容 `max-width: 1280px` 或 `1440px` 居中；MonitoringPage 可更宽；SourceDetailPage 三栏布局可设更高上限但不无限拉伸。若坚持全屏铺满，需要写明这是 Owner 新决策。
- Owner 裁定（2026-06-11）：已确认 v0.6 全部按照 Owner 提供的 UI 原型为主，D8 全屏铺满成立。**本条关闭，不再要求 UI R2 修改。**

#### #P2（中）监控角标口径需要与 L0/L1 告警承诺对齐

- 关联：D7、§4.8、AC-32、PRD §3.7。
- 问题：方案写监控角标数据源复用 v0.5 alerts 表 unhandled 计数 API，同时 AC-32 要求 MonitoringPage 告警 Tab 能看到 `task_stale / external_dep_down / task_backlog` 类告警。这里需要明确：L0/L1 相关告警是否也进入 alerts 表并计入未处理角标。
- 风险：如果 L0/L1 失败只出现在 logs 或 status counts，不进入 alerts 未处理数，Owner 会看到监控角标为 0，但实际 L1 已经有积压或外部依赖失败。
- 建议：UI R2 增补一句：监控角标 = alerts 表所有 `unhandled` 告警数，包含 v0.5 告警和 v0.6 L0/L1 自动告警；若后端暂未生成 L0/L1 alerts，角标只代表 alerts 表未处理告警，L0/L1 状态另在 Source 详情计数区呈现。

#### #P5（低）「新增信息源」与「添加展示位置」需要在文案上区分
