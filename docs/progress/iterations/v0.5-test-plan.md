## 测试执行策略

1. 先跑 L1（自动化测试 53 tests）确认全部通过

3. L3 数据库 schema 一致性
4. L4 静态代码分析补足 L1 无法覆盖的 Worker/Stream/清理脚本
5. L5 逐条 AC 判定通过/有条件通过/阻塞/无法测试

## 阻塞缺陷定义

| 严重度 | 定义 | 动作 |
|--------|------|------|
| 阻断 | 核心功能不可用、数据丢失、安全漏洞 | 阻塞测试阶段，必须修复 |
| 高 | 主要流程中断但可绕过 | 本迭代必须修 |
| 中 | 边界条件问题或次要功能异常 | 可延期，需记录 |
| 低 | 体验瑕疵 | 不阻塞定稿 |
