## 1. 概述

v0.5 是项目历史上最大的一次数据模型重构。核心变化：Source 从"空间附属配置"升级为"全局资产"，新闻从"单位置锚定"变为"多位置分发"。

| 板块 | 技术范围 | 关键决策 |
|------|---------|---------|
| A. 数据模型重构 | 10 表变更 + 3 新表，sub_channels→channels 重命名，Source 双维度状态 | 详见 §2 |
| B. API 合约重建 | 全部现有端点重写或废弃，新建 6 组 20+ 端点 | 详见 §3 |
| C. Worker 调度重构 | per-binding → per-source 调度，X Stream Manager 新建 | 详见 §4 |
| D. 数据清理 | 不可逆清空旧业务数据，事务包裹 + 备份前置 | 详见 §6 |
| E. 评分方法论 | 仅文档交付，不落地代码 | 不在本文档范围 |

**设计原则**：
- `schema.ts` 是数据模型的唯一真源，Drizzle migrate generate 产出增量迁移文件
- 所有 API 输入使用 Zod 校验
- DB 层使用 Drizzle ORM（与现有模式一致）
- 前端保持 Vue 3 Composition API + TypeScript
- 数据清理脚本使用 `pg` 原生驱动，事务包裹

### 2.2 channel_spaces

```sql
CREATE TABLE channel_spaces (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name VARCHAR(200) NOT NULL UNIQUE,
  description TEXT,
  sort_order INTEGER NOT NULL DEFAULT 0,
  icon TEXT DEFAULT '📁',
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

**变更**：新增 `sort_order`（空间排序，支持拖拽/箭头调整）、`icon`（emoji 图标，UI 展示用）。v0.4 无此两列。

### 2.3 channels（原 sub_channels）

```sql
CREATE TABLE channels (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  channel_space_id UUID NOT NULL REFERENCES channel_spaces(id) ON DELETE CASCADE,
  name VARCHAR(100) NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (channel_space_id, name)
);
```

**变更**：仅表名从 `sub_channels` 改为 `channels`，字段结构不变。所有 FK 引用 `sub_channel_id` 全局改为 `channel_id`。

**唯一约束**：`UNIQUE(channel_space_id, name)` 确保同一空间内频道名不重复。

### 2.4 sources（大幅扩展）

```sql
CREATE TABLE sources (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  -- 身份
  type VARCHAR(20) NOT NULL CHECK (type IN ('x_twitter', 'rss')),
  identity VARCHAR(500) NOT NULL,              -- 原 source_url，统一为"来源身份"
  display_name VARCHAR(200) NOT NULL,
  -- 双维度状态
  lifecycle_status VARCHAR(20) NOT NULL DEFAULT 'normal'
    CHECK (lifecycle_status IN ('normal', 'needs_fix', 'source_error', 'removed')),
  -- operational_status 为计算字段，不存储
  -- 标签
  domain_tags TEXT[] NOT NULL DEFAULT '{}',     -- 领域标签（多选）
  source_role VARCHAR(20) NOT NULL DEFAULT 'other', -- 来源角色
  content_topics TEXT[] NOT NULL DEFAULT '{}',  -- 内容主题（自由标签）
  attention_level VARCHAR(20) NOT NULL DEFAULT 'regular', -- 关注级别
  notes TEXT,                                   -- 备注
  -- 抓取配置（全局，从旧 fetch_policy 提取）
  fetch_interval_sec INTEGER,                   -- RSS 抓取周期
  max_items_per_fetch INTEGER,                  -- 单次最大抓取条数
  compensation_interval_sec INTEGER DEFAULT 86400, -- X 补偿抓取周期（默认24h）
  -- 抓取配置（保留旧 config JSONB 用于扩展）
  config JSONB NOT NULL DEFAULT '{}',
  -- 验证
  last_verified_at TIMESTAMPTZ,
  verify_error TEXT,
  -- 时间戳
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 去重索引
CREATE UNIQUE INDEX uq_sources_type_identity ON sources(type, LOWER(identity));
```

**operational_status 计算规则**：
```sql
-- 查询时动态计算，不存储
CASE
  WHEN s.lifecycle_status IN ('needs_fix', 'source_error', 'removed') THEN 'stopped'
  WHEN EXISTS(
    SELECT 1 FROM display_positions dp
    WHERE dp.source_id = s.id AND dp.enabled = true AND dp.deleted_at IS NULL
  ) THEN 'fetching'
  ELSE 'stopped'
END
```

**组合约束实现**：lifecycle_status 为 needs_fix/source_error/removed 时，operational_status 强制为 stopped（计算逻辑保证）。"未使用" = normal + stopped。

**身份变更**：`identity` 字段存储标准化身份（X 用户名小写去 @、RSS URL trim slash）。修改身份时写入 `source_identity_history`，然后更新此字段。

### 2.5 display_positions（新表，替代 channel_sources）

```sql
CREATE TABLE display_positions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  source_id UUID NOT NULL REFERENCES sources(id) ON DELETE CASCADE,
  channel_space_id UUID NOT NULL REFERENCES channel_spaces(id) ON DELETE CASCADE,
  channel_id UUID REFERENCES channels(id) ON DELETE CASCADE,  -- NULL = 空间根节点
  enabled BOOLEAN NOT NULL DEFAULT true,
  -- 软删除（历史快照）
  deleted_at TIMESTAMPTZ,
  removal_reason TEXT,  -- 'channel_deleted' | 'space_deleted' | 'manual'
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  -- 唯一约束：同一空间内，同一 Source 不能在同一位置重复
  UNIQUE (source_id, channel_space_id, channel_id)
);
-- PostgreSQL 中 NULL 参与 UNIQUE 比较时彼此不等，需部分唯一索引防止根节点重复
CREATE UNIQUE INDEX uq_dp_source_space_root ON display_positions(source_id, channel_space_id)
  WHERE channel_id IS NULL AND deleted_at IS NULL;
```

**关键变更**：
- 旧 `UNIQUE(channel_space_id, source_id)` 改为 `UNIQUE(source_id, channel_space_id, channel_id)`
- `channel_id = NULL` 表示投放至空间根节点，同一 Source 可在同一空间的根节点 and 频道同时存在
- 软删除：`deleted_at IS NOT NULL` 的记录在正常查询中过滤掉，但作为历史快照保留

**索引**：
```sql
-- 计算 operational_status 的查询依赖此索引
CREATE INDEX ix_dp_source_enabled ON display_positions(source_id, enabled, deleted_at)
  WHERE deleted_at IS NULL;
-- 获取空间+频道下的展示位置
CREATE INDEX ix_dp_space_channel ON display_positions(channel_space_id, channel_id, deleted_at)
  WHERE deleted_at IS NULL;
```

### 2.6 source_states（升至 Source 级）

```sql
CREATE TABLE source_states (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  source_id UUID NOT NULL UNIQUE REFERENCES sources(id) ON DELETE CASCADE,
  cursor JSONB NOT NULL DEFAULT '{}',
  next_fetch_at TIMESTAMPTZ,
  consecutive_failures INTEGER NOT NULL DEFAULT 0,
  last_success_at TIMESTAMPTZ,
  last_error TEXT,
  last_fetch_count INTEGER,  -- 最近一次抓取产出条数
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()

CREATE INDEX ix_source_states_next_fetch ON source_states(next_fetch_at);
```

**变更**：`channel_source_id` → `source_id`（UNIQUE），从 per-binding 升为 per-source。新增 `last_fetch_count`（SourceCard 展示用）。

### 2.7 raw_items

```sql
CREATE TABLE raw_items (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  source_id UUID NOT NULL REFERENCES sources(id) ON DELETE CASCADE,
```

### 2.8 processed_news

```sql
CREATE TABLE processed_news (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  raw_item_id UUID NOT NULL UNIQUE REFERENCES raw_items(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  summary TEXT NOT NULL,
  language VARCHAR(20) NOT NULL DEFAULT 'zh',
  source_refs JSONB NOT NULL DEFAULT '{}',
  published_at TIMESTAMPTZ,
  bullets JSONB NOT NULL DEFAULT '[]',
  tags JSONB NOT NULL DEFAULT '[]',
  entities JSONB NOT NULL DEFAULT '[]',
  importance_score NUMERIC NOT NULL DEFAULT '0',
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()

```

**变更**：移除 `channel_space_id` 和 `channel_id`。新闻不再锚定单一位置。位置关联通过 `news_positions` 实现。

### 2.9 news_positions（新 m:n 关联表）

```sql
CREATE TABLE news_positions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  news_id UUID NOT NULL REFERENCES processed_news(id) ON DELETE CASCADE,
  position_id UUID NOT NULL REFERENCES display_positions(id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (news_id, position_id)
);
CREATE INDEX ix_np_position_news ON news_positions(position_id, news_id);
CREATE INDEX ix_np_news ON news_positions(news_id);
```

**用途**：一条新闻关联多个展示位置。浏览页查询特定频道时通过此表 JOIN：
```sql
-- 浏览页 "全部" Tab：聚合空间根节点 + 全部频道新闻，去重
SELECT DISTINCT pn.* FROM processed_news pn
JOIN news_positions np ON np.news_id = pn.id
JOIN display_positions dp ON dp.id = np.position_id
WHERE dp.channel_space_id = $space_id
  AND dp.deleted_at IS NULL
  AND dp.enabled = true
ORDER BY pn.published_at DESC;

-- 浏览页特定频道：只展示该频道新闻
-- dp.channel_id = $channel_id（空间根节点需单独处理 dp.channel_id IS NULL）
```

### 2.10 tasks

```sql
CREATE TABLE tasks (

  last_error TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),

CREATE INDEX ix_tasks_queue ON tasks(status, run_after, priority);
CREATE INDEX ix_tasks_locked_at ON tasks(locked_at);
```

**变更**：移除 `channel_space_id`、`channel_source_id`。新增 `source_id`（直接关联 Source，task 不再需要知道展示位置）。

### 2.11 alerts

```sql
CREATE TABLE alerts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  scope VARCHAR(20) NOT NULL DEFAULT 'source' CHECK (scope IN ('source', 'x_stream', 'system')),
  source_id UUID REFERENCES sources(id) ON DELETE SET NULL,
  channel_space_id UUID REFERENCES channel_spaces(id) ON DELETE SET NULL,  -- 改为 nullable
  type TEXT NOT NULL,
  severity TEXT NOT NULL DEFAULT 'warning',
  status VARCHAR(20) NOT NULL DEFAULT 'active' CHECK (status IN ('active', 'acknowledged', 'resolved', 'ignored')),
  message TEXT NOT NULL,
  meta JSONB NOT NULL DEFAULT '{}',
  -- 去重
  dedup_key TEXT,        -- 同源去重标识（如 "source_error:{source_id}:404"）
  last_triggered_at TIMESTAMPTZ,
  resolved_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX ix_alerts_scope_source ON alerts(scope, source_id, status);
CREATE INDEX ix_alerts_unread ON alerts(status, created_at) WHERE status = 'active';
CREATE INDEX ix_alerts_dedup ON alerts(dedup_key) WHERE status = 'active';
```

**变更**：
- `channel_space_id` 改为 nullable（X Stream 全局告警不需要空间）
- 新增 `scope` 字段：`source`（Source 级异常）、`x_stream`（X Stream 全局）、`system`（数据库/队列异常）
- 新增 `source_id` FK
- 新增 `dedup_key` + `last_triggered_at`：支持 24h 告警去重
- 新增 `resolved_at`：记录恢复时间
- status 枚举值扩展：`active`（未处理）、`acknowledged`（已确认）、`resolved`（已恢复）、`ignored`（已忽略）

**告警去重逻辑**：
```sql
-- 24h 内同源再次异常 → 更新原告警而非新建
UPDATE alerts
SET status = 'active', last_triggered_at = now(), message = $new_message
WHERE dedup_key = $key
  AND status IN ('resolved', 'ignored')
  AND last_triggered_at > now() - INTERVAL '24 hours';

-- 无匹配原告警 → 新建
-- (INSERT)
```

```sql
CREATE TABLE source_identity_history (
```

## 4. 核心流程

### 4.1 Worker 调度模型变更

**v0.4**：Scheduler 遍历 `channel_sources` → 每个 binding 独立调度 → `source_states` 记录 per-binding 状态。

**v0.5**：Scheduler 遍历 `sources`（仅 `lifecycle_status = 'normal'` 且 `operational_status = 'fetching'`）→ Source 级调度 → `source_states` 记录 per-source 状态。

```text
┌─ Scheduler ──────────────────────────────────────┐
│ 1. 查询 sources WHERE lifecycle_status='normal'   │
│    AND EXISTS(enabled display_position)           │
│    AND (source_states.next_fetch_at IS NULL       │
│         OR source_states.next_fetch_at <= now())  │
│                                                   │
│ 2. 对每个 Source：                                │
│    ├─ RSS: 创建 fetch_rss task                   │
│    └─ X: 仅补偿抓取（过滤那些不在 Stream 中的）     │
│                                                   │
│ 3. source_states.next_fetch_at = now() + interval │
└──────────────────────────────────────────────────┘
```

**自动启停**：
- 最后启用位置被暂停/移除 → operational_status 变为 `stopped` → Scheduler 不再调度
- 首个启用位置出现 → operational_status 变为 `fetching` → Scheduler 开始调度

### 4.2 抓取→处理→分发流程

```text
┌─ Fetcher ────────────────────────────────────────┐
│ RSS: fetch URL → parse → yield raw_items[]       │
│ X: call timeline API → yield raw_items[]          │
│                                                   │
│ 状态更新：                                        │
│ 状态更新（对齐 PRD §4.6 失败计数口径）：            │
│ - 完整成功（含部分内容解析失败）→                   │
│   consecutive_failures = 0, last_success_at=now()  │
│   lifecycle_status 保持/恢复 normal                │
│ - 整体失败（网络/5xx/429/401/403）→                 │
│   consecutive_failures += 1                        │
│   达到 3 → lifecycle_status = source_error         │
│          → 生成告警                                 │
│                                                    │
│ 注：单条内容解析失败不计入连续失败（PRD §4.6）。    │
│ "部分内容成功+部分失败"视为完整成功。               │
└──────────────────────────────────────────────────┘
    ↓ raw_items[]
┌─ Processor ──────────────────────────────────────┐
│ 对每条 raw_item：                                 │
│ 1. 去重（source_item_id）                         │
│ 2. LLM 处理 → processed_news                     │
│ 3. 查找该 Source 的所有启用 display_position     │
│ 4. 对每个 position 创建 news_positions 记录       │
│ 5. 更新 source_states.cursor / last_fetch_count  │
└──────────────────────────────────────────────────┘
```

### 4.3 X Stream Manager（新建）

```text
┌─ XStreamManager（Worker 启动时初始化）───────────┐
│                                                   │
│ 生命周期：                                        │
│ 1. start():                                       │
│    ├─ 查询所有 lifecycle_status='normal'           │
│    │   且有启用 display_position 的 X Source       │
│    ├─ 构建规则: from:{username} -is:retweet       │
│    │            -is:reply                         │
│    ├─ POST filtered/stream/rules (批量设置)       │
│    └─ GET filtered/stream (建立长连接)            │
│                                                   │
│ 2. 规则同步（debounced, 30s 窗口）：               │
│    ├─ 新启用 X Source → 添加规则                  │
│    ├─ 最后位置暂停/移除 → 删除规则                │
│    └─ 调用 GET rules + POST rules 同步            │
│                                                   │
│ 3. 推文接收：                                     │
│    ├─ Stream 推送 → 解析 → 创建 raw_items         │
│    │               → enqueue tasks (type: process) │
│    └─ 与 compensation 抓取共享 source_item_id     │
│       去重（UNIQUE(source_id, source_item_id)）    │
│                                                   │
│ 4. 断线重连：指数退避（1s→2s→4s...max 60s）       │
│    ├─ 重连成功后全量同步规则                       │
│    └─ 连续断开触发 x_stream 全局告警               │
│                                                   │
│ 5. stop(): 断开 Stream 连接                        │
└──────────────────────────────────────────────────┘
```

**单实例保证**：systemd `Restart=always` + 单进程部署。后续扩容需选主机制（不在本轮范围）。

**Stream 异常不与 systemd 交互**：Stream 断线由应用层自愈（指数退避重连），不触发进程退出。systemd 仅介入进程崩溃场景（OOM、未捕获异常），此时 ExecStartPre 执行 drizzle-kit migrate 后冷启动。

**X API 依赖**：
- `X_BEARER_TOKEN` 环境变量（必需）
- Filtered Stream v2 endpoint
- Rules management endpoint
- User timeline endpoint（补偿抓取）

### 4.4 告警生命周期

```text
Fetcher 异常 ─→ 生成/更新 alert ─→ status='active'
  │                                     │
  ├─ 管理员"确认" ─→ acknowledged        │
  ├─ 管理员"忽略" ─→ ignored             │
  └─ 抓取恢复 ─→ 若 active → resolved    │
                 若 acknowledged → 保持（不自动变更）
              
去重窗口（24h）：
  resolved/ignored + 同 dedup_key + 24h 内再次异常
  ─→ UPDATE status='active', last_triggered_at=now()
  （不新建告警记录）
```

### 4.5 展示位置自动启停

```text
事件: display_position.enabled 变更 / 创建 / 删除

触发器：每次变更后重新计算该 Source 的 operational_status
  ├─ 至少 1 个 enabled AND deleted_at IS NULL
  │   → fetching（Scheduler 开始调度，X Stream 添加规则）
  └─ 0 个 enabled
      → stopped（Scheduler 停止调度，X Stream 移除规则）
```

不提供独立的手动"总开关"——完全由展示位置自动推导。

### 4.6 频道删除迁移逻辑

PRD §4.9 要求删除频道时允许将展示位置迁移到空间根节点。事务边界如下：

```text
DELETE /api/spaces/:id/channels/:cid  { action: 'migrate_to_root' }
  │
  ├─ BEGIN
  ├─ 1. 冲突检测：
  │     SELECT dp.source_id FROM display_positions dp
  │     WHERE dp.channel_id = $cid AND dp.deleted_at IS NULL
  │     AND EXISTS(
  │       SELECT 1 FROM display_positions dp2
  │       WHERE dp2.source_id = dp.source_id
  │         AND dp2.channel_space_id = $space_id
  │         AND dp2.channel_id IS NULL
  │         AND dp2.deleted_at IS NULL
  │     )
  │     → 有结果 → 返回 409 + 冲突 Source 列表，终止
  │
  ├─ 2. migration：UPDATE display_positions
  │     SET channel_id = NULL
  │     WHERE channel_id = $cid AND deleted_at IS NULL
  │     → 迁移后保留 enabled 状态不变
  │
  ├─ 3. 移除（未迁移的）：UPDATE display_positions
  │     SET deleted_at = now(), removal_reason = 'channel_deleted'
  │     WHERE channel_id = $cid AND deleted_at IS NULL
  │
  ├─ 4. DELETE FROM channels WHERE id = $cid
  └─ COMMIT
```

**action='remove_all'** 时跳过步骤 2，全部位置软删除。两种模式均在一个事务中完成，任意步骤失败 → ROLLBACK。

## 6. 迁移和兼容性

### 6.1 数据库迁移策略

v0.5 不执行旧业务数据迁移。采用以下步骤：

```
Step 1: 备份生产数据库（pg_dump）
Step 2: 清空旧业务数据（§6.2 清理脚本）
Step 3: Drizzle generate 产出增量迁移 SQL
Step 4: Drizzle migrate 执行 schema 变更（建新表、删旧表）
Step 5: 验证（§6.3）
```

**注意**：v0.5 不产生从旧 schema 到新 schema 的数据迁移 SQL。旧数据全部清空，从空白状态启动。

### 6.2 数据清理脚本

```sql
-- 清理脚本只针对旧 schema 中实际有数据的表（按 FK 依赖从子到父）。
-- 新表（news_positions / display_positions / source_identity_history / channels）
-- 由 Step 4 drizzle migrate 创建后自然为空，此脚本不涉及。
-- 
-- 表名对照：sub_channels → channels（旧表已存在，按旧名清理）
BEGIN;

DELETE FROM alerts;                    -- FK→channel_spaces, sources（旧 schema 实际有数据）
DELETE FROM processed_news;            -- FK→raw_items（旧 schema 实际有数据）
DELETE FROM tasks;                     -- FK→channel_spaces, channel_sources, raw_items（旧 schema）
DELETE FROM raw_items;                 -- FK→sources（旧 schema 实际有数据）
DELETE FROM source_states;             -- FK→channel_sources（旧 schema 实际有数据）
DELETE FROM channel_sources;           -- FK→channel_spaces, sub_channels, sources（旧 schema）
DELETE FROM sub_channels;              -- FK→channel_spaces（旧表名，将被 rename 为 channels）
DELETE FROM sources;                   -- 独立
DELETE FROM channel_spaces;            -- 独立

COMMIT;
```

**安全措施**：
1. 脚本执行前必须先完成 `pg_dump` 备份
2. 整个清理包裹在事务中，任意步骤失败 → ROLLBACK
3. DevOps 执行前输出每表行数统计，Owner 确认后执行
4. 脚本进入 Git 管理（`server/db/scripts/reset-business-data.sql`）

## 7. 风险和取舍

### 7.1 设计决策

| 决策 | 选项 A（采纳） | 选项 B（未采纳） | 取舍理由 |
|------|---------------|-----------------|---------|
| operational_status 存储方式 | 查询时动态计算 | 存储在 sources 表中 | 计算字段避免缓存不一致；查询性能由 display_positions 索引保证；Source 数量级（<10K）下子查询开销可忽略 |
| 历史展示位置快照 | 软删除（deleted_at） | 独立快照表 | 软删除实现更简单，无需维护两张表的字段同步；历史快照查询只需忽略 deleted_at 过滤；删除的 space/channel 名称通过 JOIN 获取（若已删除则显示"已删除"） |
| 告警去重实现 | dedup_key 字段 + 24h 窗口 | 查询最近告警判断 | dedup_key 可以用索引精确匹配，避免扫描；24h 窗口在应用层判断并 UPDATE 而非 INSERT |
| X Stream 规则同步 | debounced 30s 批量同步 | 实时逐条同步 | X API 有速率限制；30s 内多次 Source 变更合并为一次全量规则同步；PRD AC 允许 30s 延迟 |
| 数据清理方式 | DELETE 逐表清理（事务包裹） | TRUNCATE CASCADE | TRUNCATE 无法在事务中回滚；DELETE 虽慢但数据量小（Owner 确认无保留价值），且可在失败时完整回滚 |

### 7.2 风险登记

| 风险 | 影响 | 缓解 |
|------|------|------|
| X API Filtered Stream 套餐不支持 | X 主线无法上线 | DevOps 上线前核验 Developer Console（PRD 前置依赖 #2） |
| display_positions 软删除导致历史数据膨胀 | 查询变慢 | 索引 WHERE deleted_at IS NULL 过滤活跃数据；定期归档旧快照（后续迭代） |
| Worker per-source 调度 + X Stream 并发 | 同一 Source 的 RSS 和 Stream 推文并发处理 | source_item_id UNIQUE 约束自然去重 |
| 数据清理脚本在生产执行 | 不可逆 | pg_dump 备份 + 事务回滚 + Owner 双重确认 |
| 全量 API 重写导致前端全部不可用 | 上线窗口长 | 前端+后端同步上线；无旧兼容包袱 |
