### 1.2 关键任务流程

#### 创建信息源（路径 A：从信息源库）

```
信息源库 Tab → 点击"新建信息源"
  → 弹出 SourceCreateForm Modal
  → 填写类型、身份、名称、标签
  → 点击"验证"
  ├─ 成功 → Source 保存为"正常" → Modal 关闭 → 表格刷新
  └─ 失败 → 显示错误 + 两个选项
       ├─ "保存为待修复" → Source 保存 → Modal 关闭
       └─ "重试" → 回到验证步骤
```

#### 创建信息源（路径 B：从空间管理页）

```
空间管理 Tab → 选择空间+频道 → 点击"添加信息源"
  → 弹出搜索面板：搜索已有 Source
  ├─ 找到 → 选中 → 立即添加为展示位置
  └─ 未找到 → 点击"新建信息源"
       → 弹出 SourceCreateForm Modal
       → 填写 + 验证
       ├─ 成功 → Source 保存 + 自动添加到当前位置 → Modal 关闭
       └─ 失败 → 保存为待修复 → Toast "已保存为待修复，修复后可重新添加" → 回到管理页
```

#### 删除频道（含迁移）

```
频道 Pill → 点击删除图标
  → Modal 展示影响预览（N 个展示位置受影响）
  → 选择处理方式：
      ○ 迁移到 {空间名} 根节点
      ○ 直接移除全部展示位置
  → 如有冲突（Source 已在根节点存在）：
      阻止迁移，提示冲突 Source 列表，迁移按钮不可用
  → 无冲突时：输入频道名称确认 → 执行删除
```

#### 删除 Source

```
Source 详情页 / 表格行 → 点击删除
  → Modal 展示影响预览：
      - 将移除的展示位置数量
      - 保留的历史新闻数量
  → 输入 Source 展示名称确认 → 执行删除
  → Source 标记为"来源已移除"，全部位置移除，历史新闻保留
```

#### 告警状态流转

```
系统生成告警 → 未处理 ──确认──→ 已确认 ──标记恢复──→ 已恢复
                 │                  │
                 └──忽略──→ 已忽略   │
                             │      │
                             └──重新打开──→ 未处理

自动恢复规则：
- 未处理 + 抓取成功 → 系统自动标记为已恢复
- 已确认 + 抓取成功 → 保持已确认（不自动变更，管理员曾关注）
- 恢复后 24h 内同源再次异常 → 更新原告警而非新建
```

### 3.3 Source 双维度状态展示规则

**表格列展示**：可用性状态和运行状态分两列独立展示。

| 可用性状态 | Badge 颜色 | 显示文字 |
|-----------|-----------|----------|
| 正常 | 绿（`--success-light` / `--success`） | 正常 |
| 待修复 | 橙（`--warning-light` / `--warning`） | 待修复 |
| 来源异常 | 红（`--danger-light` / `--danger`） | 来源异常 |
| 来源已移除 | 灰（`#F1F5F9` / `--text-muted`） | 已移除 |

| 运行状态 | 指示器 | 显示文字 |
|----------|--------|----------|
| 抓取中 | ● 绿点（`--success`） | 抓取中 |
| 已停止 | ● 灰点（`--text-muted`） | 已停止 |

**组合规则**：

| 可用性 ↓ / 运行 → | 抓取中 | 已停止 |
|-------------------|--------|--------|
| 正常 | 正常 + 抓取中 | **正常 + 已停止**（= 未使用） |
| 待修复 | —（不可能） | 待修复 + 已停止 |
| 来源异常 | —（不可能） | 来源异常 + 已停止 |
| 来源已移除 | —（不可能） | 已移除 |

"未使用"不作为一个独立状态值，而是以"正常"（绿） + "已停止"（灰点）的视觉组合表示。在筛选时，选择"可用性=正常 AND 运行=已停止"等价于"未使用"。

**详情页展示**：页头同时展示两个 Badge。可用性为"来源异常"或"待修复"时，在页头下方展示醒目的黄色注意条。

**筛选器**：可用性状态和运行状态作为两个独立的筛选组，支持任意组合。

### 3.4 告警状态流转规则

| 当前状态 | 管理员可执行动作 | 系统自动动作 |
|----------|-----------------|-------------|
| 未处理 | 确认、忽略 | 抓取成功 → 自动标记已恢复 |
| 已确认 | 标记恢复、忽略 | 抓取成功 → 保持已确认（不自动变更） |
| 已恢复 | 无（终态） | — |
| 已忽略 | 重新打开为未处理 | — |

**状态 Badge 颜色映射**：

| 告警状态 | 背景色 | 文字色 | 图标 |
|----------|--------|--------|------|
| 未处理 | `--danger-light` | `--danger` | ● |
| 已确认 | `--warning-light` | `--warning` | ◉ |
| 已恢复 | `--success-light` | `--success` | ✓ |
| 已忽略 | `#F1F5F9` | `--text-muted` | ✕ |

**顶栏角标**：仅统计"未处理"状态数量，红底白字圆角 Badge，无未处理时不显示。

### 6.4 DeleteConfirmDialog.vue

删除确认弹窗，扩展 useModal 模式以支持影响预览和名称确认。

**Props**：

| Prop | 类型 | 说明 |
|------|------|------|
| `title` | `string` | 弹窗标题 |
| `targetName` | `string` | 删除对象名称 |
| `impact` | `{ affectedPositions: number, preservedNews: number, additionalInfo?: string }` | 影响预览数据。组件内部渲染，不使用 v-html |
| `confirmName` | `string` | 需用户输入的名称 |

**Props 说明**：`impact` 为结构化数据，组件根据 `affectedPositions` 和 `preservedNews` 内部渲染影响预览文案，避免外部拼接 HTML 导致 XSS 风险。
| `danger` | `boolean` | 是否为危险操作，默认 `true` |

## 7. 交互细节规约

### 7.1 搜索与筛选 AND/OR 逻辑

| 组合 | 逻辑 | UX 表达 |
|------|------|---------|
| 搜索关键词 × 筛选条件 | AND | 筛选栏提示"多个条件为「且」关系" |
| 多个筛选维度之间 | AND | 同上 |
| 同维度内多选值 | OR | 提示"同类多选为「或」关系" |

### 7.2 分页交互

- 首次加载默认第 1 页，每页 20 条
- 切换每页条数后自动回到第 1 页
- 页码按钮显示逻辑：始终显示第 1 页和最后一页，中间显示当前页 ±2 页，超出部分用 `...` 省略
- 总条数为 0 时不显示分页控件，显示空状态

### 7.3 排序

- 空间 Pill 和频道 Pill 支持排序
- hover 时 Pill 左侧出现 ← → 箭头按钮
- 点击箭头调用 API 持久化排序
- 失败回滚：恢复原顺序 + Toast 错误提示
- "全部" Pill 始终位于频道行首位，不可移动
- 拖拽排序留后续迭代

### 7.4 确认即删除

所有删除操作（Source、频道、空间）遵循统一模式：

1. 展示影响预览（哪些数据会被影响）
2. 要求输入名称确认
3. 输入不匹配时确认按钮不可用
4. 确认按钮为红色 danger 样式
5. 执行后 Toast 反馈结果

### 7.5 创建→验证→保存 双路径

| 步骤 | 路径 A（信息源库） | 路径 B（空间管理） |
|------|-------------------|-------------------|
| 触发 | "新建信息源"按钮 | "添加信息源" → "新建信息源" |
| 创建+验证成功 | 进入信息源库，不添加到任何位置 | 自动添加到当前空间+频道 |
| 创建+验证失败 | 可选保存为待修复 | 保存为待修复 + Toast 提示修复入口 |
