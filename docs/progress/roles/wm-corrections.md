## 2026-05-31 — 基线规则未明确"基线同步"权限边界，导致 Developer 越界做了
- 现象：2026-05-30 Developer 角色顺手做了"从 claude-code-one-person-company-workflow 同步基线"操作，连带误删生产源码 server/ 38 文件。事后追因发现 baseline 各文件**从未明确写过"基线同步是 WM 专属职责，其他角色不得越界做"**——只在 `role-wm.md` 写了 WM 负责维护工作流，但没禁止其他角色做。Developer 没看到"禁止"自然就做了。详见 [Incident 2026-05-31](../ad-hoc/2026-05-31-incident-server-source-deleted-by-baseline-sync.md)。
- 修正：2026-05-31 commit `dfede2b` 落地三项基线修正——其中 #1「受保护路径删除 Review 门禁」覆盖 `docs/baseline/`、`docs/templates/`、`CLAUDE.md` 路径，等于事实上**通过门禁机制约束了"只有架构师 Review 通过才能改基线"**，从规则层把 Developer 顺手改基线这条路堵上了。
- 预防：
  1. **规则不能只写"谁负责"，必须同步写"谁不可以"**——`role-wm.md` 写了 WM 维护基线，但没写"其他角色禁止单方面改基线"；本次事故就是这个缺口导致。下次新增角色职责时，必须同步明确"其他角色不可越界的边界"
  2. **基线层敏感操作必须双向门禁**——既要在 WM 手册写"WM 怎么做"，也要在其他角色手册的"安全边界 / 禁止事项"里写"不能做什么"（commit `dfede2b` 已在 role-developer.md §安全边界、role-wm.md §安全边界 各加一行引用）
  3. **审查工作流时优先看"权限缺口"**——下次做流程审计，重点扫描"哪类操作没有清晰归属，可能被多个角色都'顺手'做"

## 2026-05-31 — WM 自身做基线修正时未先查清"修改影响是否对称"
- 现象：本次三项基线修正提案中，#1 删除门禁规则改 `role-architect.md`（指定架构师为 Review 方）和 `role-wm.md`（WM 自身受同门禁约束）；起草初版时漏了这两个文件，是 Owner 交互过程中才补上的。
- 修正：第二轮交互中补充了 role-architect.md 「受保护路径删除 Review 职责」章节 + role-wm.md §安全边界一行；最终 commit `dfede2b` 完整覆盖。
- 预防：
  1. **每条新规则都做"双侧检查"**：规则要求 X 做 Y 时，自问「X 知不知道？」（→ X 的手册要写）+「被 X 影响的角色知不知道？」（→ 那些角色的手册也要写）
  2. **WM 修改基线时套用"角色矩阵 ✕ 影响维度"** 表，每修改一条规则填一行：触发角色 / 执行角色 / 被审角色 / 兜底角色，四个位置都对照检查手册是否有对应条款
