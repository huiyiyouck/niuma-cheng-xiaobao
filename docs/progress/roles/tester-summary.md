## Tester 边界守住经验

- **不代 PM/Developer Review**：用户口语"处理一下"易诱导越权。先反问范围再行动（2026-05-31 翻牌时差点跨界）。
- **R2 复审控边界**：核验 R1 关闭状态 + 评估新增 AC 可测试性，不重复 R1 Review 内容。新发现与其他角色一致时主动标注"与 X 同源"。
- **翻牌定稿是 Tester 本职**：产出方落定文档状态，不属于越权。
- **PRD Review 严格在"AC 可测试性和覆盖完整性"范围内**：不评判产品范围、技术方案、UI 交互。

## 测试常见风险

1. **AI 输出"正确性"不可自动化**：结构层可断言（字段存在 / 类型匹配 / 值域合法），内容正确性需人工抽样或 golden dataset。
2. **外部依赖测试**：LLM/搜索/链接读取在 CI 无 Token、无网络保障，必须 mock。
3. **状态机定义缺失**：PRD 用"通过/失败/skipped/processing/completed/最终失败"等散文式状态词，必须收敛为枚举表 + 转移图，否则 AC 不可写断言。
4. **不回归边界缺失**：PRD 不要求"既有测试 100% 通过"和"既有功能不退化"会让历史测试腐烂。每次 PRD Review 都要主动追问。
5. **失败场景"仅记录"不足**：异常 AC 要要求系统协同响应（如不阻塞其他任务、不污染其他类型的退避）。
6. **前端验收手段不明**：API 层测试只覆盖数据正确，渲染正确层需要明确人工 / Storybook / Playwright。
7. **空间/上传类异常**：除类型/大小超限，还要覆盖网络中断、存储不可写、并发覆盖、损坏文件 4 类。
8. **延后 vs 放弃语义**：延后必须落档到具体迭代或触发条件，否则会变成永久遗忘项。
