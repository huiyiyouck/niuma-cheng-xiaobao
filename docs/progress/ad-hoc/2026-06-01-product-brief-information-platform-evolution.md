## 1. 产品定位

**有价值的结构化信息平台，不是信息堆砌。**

从多源采集 → AI 评测分级 → 结构化卡片 → 多渠道推送，为需要高质量信息的人提供筛选后的信息服务。

## 2. 演进路线

```text
阶段 1：自用打磨（当前 → v1.0）
  - 做好 AI + 财经两个频道空间
  - 建立信息评测体系
  - X/Twitter + RSS 信息源逐步接入
  - 全自动化运行，自己使用验证

阶段 2：对外输出（v1.0 后）
  - 微信订阅号：每日推送
  - 微信公众号：深度文章引流
  - RSS 输出：技术用户入口
  - 确认用户画像后决定下一步

阶段 3：商业化（用户画像明确后）
  - 付费订阅：实时推送 / 深度分析
  - 渠道扩展：飞书 / Webhook / 服务号
  - 定价根据用户反馈确定
```

**v1.0 里程碑**：自用跑通 + 可以通过订阅号开始推送引流。

## 3. 频道空间规划

| 空间 | 领域 | 信息源 | 状态 |
|------|------|--------|------|
| AI | 人工智能行业动态 | X/Twitter + RSS（逐步积累） | 已有基础，需增强 |
| 财经 | 财经市场动态 | X/Twitter + RSS（信息源待确认） | 待建设 |

两个空间独立运营，不做交叉。每个空间的信息源逐步积累，用户认为有意义的再引入。

## 4. 信息评测体系

### 4.1 核心设计原则

**全自动化：代码主导，LLM 辅助，人工不参与。**

```text
信息进入 → 代码分流 → LLM 处理 → 代码判状态 → 自动推送决策
```

- 代码做规则明确的筛选和路由
- LLM 只做需要理解力的打分和内容处理
- 人工不审核、不修正、不决策

### 4.2 处理链路

```text
┌─────────────────────────────────────────────────────┐
│  1. 信息进入（X/RSS）                                │
│  2. 代码分流：去重 → 过滤 → 分类 → 预处理 → 排队    │
│  3. LLM 处理：打分 + 摘要 + 标签 + 实体              │
│  4. 代码判状态：综合分 + 单维度突出 → 状态流转       │
│  5. 自动推送决策：立即推送 / 日报 / 仅入库 / 待确认  │
└─────────────────────────────────────────────────────┘
```

### 4.3 代码分流

代码在 LLM 之前执行，减少 LLM 调用成本，提高处理效率：

| 分流动作 | 说明 |
|----------|------|
| 去重 | URL / 消息 ID 去重，同一条不处理两遍 |
| 过滤 | 按规则过滤明显垃圾（转发、广告、无正文） |
| 分类 | 按空间归属分发（AI vs 财经） |
| 预处理 | 提取关键字段（标题、正文、来源、时间），给 LLM 干净输入 |
| 优先级排队 | 信息源等级排优先级（官方源 > KOL > 普通账号），紧急的先处理 |

### 4.4 维度评分

**当前维度（3 个）**：

| 维度 | 编号 | 评分范围 | 评测什么 |
|------|------|----------|----------|
| 时效性 | D1 | 1-5 | 消息的新鲜度和时间敏感度 |
| 影响力 | D2 | 1-5 | 影响范围的大小 |
| 置信度 | D3 | 1-5 | 信息源的可靠程度 |

**预留维度（后续启用）**：

| 维度 | 编号 | 启用条件 |
|------|------|----------|
| 行动性 | D4 | 有付费用户需要"这信息我该做什么"时 |
| 稀缺性 | D5 | 内容同质化严重、需要差异化时 |

评分范围统一 1-5，后续加维度不用改评分体系。

### 4.5 综合分计算

```text
综合分 = w1×D1 + w2×D2 + w3×D3

当前权重：等权（w1 = w2 = w3 = 1），后续可调
综合分范围：3-15
```

**单维度突出检测**：任一维度 = 5 时触发标记，即使综合分未达阈值，也进入高优处理。

### 4.6 评分锚点

每个维度需要明确的评分锚点定义，LLM 才能稳定打分。评分锚点是评测体系的核心资产，需要持续积累校准。

示例（待细化）：

```text
D1 时效性：
1 = 24小时前的信息
2 = 12小时内
3 = 4小时内
4 = 1小时内
5 = 刚发生 / 首发信源

D2 影响力：
1 = 仅影响特定项目/公司
2 = 影响某个小领域
3 = 影响一个子行业
4 = 影响整个行业
5 = 影响跨行业 / 全局性事件

D3 置信度：
1 = 匿名爆料 / 未经任何验证
2 = 单一非官方来源
3 = 可信 KOL 或预印本
4 = 多源报道交叉验证
5 = 官方来源 / 一手信息
```

### 4.7 阈值与权重

当前占位，待积累数据后校准：

| 参数 | 占位值 | 说明 |
|------|--------|------|
| 阈值 A（立即推送） | 综合分 ≥ 13 | 待校准 |
| 阈值 B（日报收录） | 综合分 ≥ 8 | 待校准 |
| D3 硬拦截 | D3 ≤ 2 → 待确认 | 先做，自用后调整 |
| 维度权重 | 等权 | 待校准 |

### 4.8 校准方式

全自动模式不靠人工审核校准，靠使用反馈：

- 推送了但觉得没用 → 阈值或权重偏了
- 漏推了重要的 → 阈值太高或锚点不准
- 推了假的 → D3 锚点要收紧

定期回顾反馈，调整参数。

## 5. 信息状态体系（草稿）

| 状态 | 触发条件 | 动作 |
|------|----------|------|
| 🔴 立即推送 | 综合分 ≥ 阈值A 或 任一维度 = 5 | 自动推送 + 入库 + 标记为展开候选 |
| 🟡 日报收录 | 综合分 ≥ 阈值B 且 < 阈值A | 入库 + 纳入当期日报 |
| ⚪ 仅入库 | 综合分 < 阈值B | 入库，不主动推送 |
| 🔵 待确认 | D3 ≤ 2 | 入库 + 标记待确认，不推送 |

**待确认在全自动模式下的含义**：系统等待更多信源交叉验证，验证通过后自动升级状态，不需要人工介入。

> 以上状态体系为草稿，后续讨论确认。

## 6. 展开逻辑（草稿）

"展开"= 标记为值得深度处理（写文章素材），不等于自动生成文章。

| 触发条件 | 说明 |
|----------|------|
| 综合分 ≥ 阈值A | 高价值信息，值得展开 |
| 任一维度 = 5 | 某方面极端突出，值得展开 |

展开后的深度内容（文章/分析）生成时机待定，可能是自动化也可能是手动触发，后续迭代讨论。
