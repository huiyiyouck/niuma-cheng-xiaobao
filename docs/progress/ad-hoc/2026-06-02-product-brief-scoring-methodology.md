## 1. 目标

评分不是为了立即决定推送、日报或自动分流，也不是为了输出一个看起来精确的数字。

本方法论的目标是：

> 为每条信息建立结构化价值画像，为后续排序、筛选、回顾、校准和事件分析积累数据基础。

本轮只定义“如何评价单条信息”，不定义评分结果的用途。

## 2. 范围边界

### 2.1 本轮包含

- 评分对象。
- 首版评分维度。
- 未来预留维度。
- 每个首版维度的 `1-5` 分锚点。
- LLM 输入和输出边界。
- 空间和频道的场景权重。
- 权重方案与权重版本管理。
- 评分记录、场景分记录和上下文快照。
- 评分方法版本和未来校准方向。

### 2.2 本轮不包含

- 日报模块。
- 推送渠道。
- 自动分流。
- 新闻状态流转。
- 分数阈值。
- 页面如何展示评分。
- Source 关注级别系数。
- 历史新闻批量重评。
- 评分代码落地。

## 3. 评分对象

评分对象是单条进入平台的信息。

例如：

```text
@OpenAI 发布新模型
某财经媒体发布利率变动快讯
某研究机构发布论文
```

Source、空间和频道不直接参与信息维度评分。

Source 标签可以作为 LLM 理解来源背景的上下文，但不能机械地固定某个维度分数。

## 4. 候选维度

### 4.1 五个候选维度

| 维度 | 英文标识 | 核心问题 | 当前状态 |
|------|----------|----------|----------|
| 时效性 | `timeliness` | 这条信息是否新鲜？是否需要尽快知道？ | 首版启用 |
| 影响力 | `impact` | 如果信息成立，可能影响多大范围？ | 首版启用 |
| 置信度 | `confidence` | 这条信息本身是否可靠？ | 首版启用 |
| 行动性 | `actionability` | 用户知道后，是否可能需要采取行动？ | 预留 |
| 独特性 | `uniqueness` | 相比已有信息，这条内容提供了多少新增信息？ | 预留 |

原先讨论的“稀缺性”调整为“独特性”。“独特性”更准确地表达新增信息量和差异化价值，也更适合未来与事件聚类、重复报道识别和影响链分析结合。

### 4.2 首版只启用三个维度

首版启用：

```text
时效性
影响力
置信度
```

暂不启用行动性：

- 当前用户画像尚未明确。
- “采取行动”的对象和场景尚未稳定。
- 日报、推送和后续工作流尚未规划。

暂不启用独特性：

- 单靠一条信息无法稳定判断新增信息量。
- 需要相似内容识别、历史对照或事件聚类能力。
- 后续可以与“事件时间线与影响链分析”一起设计。

### 4.3 暂不增加更多维度

以下概念暂不独立设为评分维度：

| 概念 | 暂不加入的原因 |
|------|----------------|
| 相关性 | 更适合作为空间或频道视角下的匹配度 |
| 热度 | 容易受到传播规模误导，并依赖外部数据 |
| 情绪倾向 | 属于内容分析字段，不代表价值 |
| 深度 | 长文不一定重要，短快讯也可能价值很高 |
| 来源权威性 | 更适合作为置信度判断上下文 |
| 商业价值 | 用户画像和商业模式尚未确定 |
| 风险程度 | 待积累数据后再判断是否需要独立建模 |

## 5. 首版维度锚点

每个维度使用 `1-5` 的整数分：

```text
1 = 很低
2 = 较低
3 = 中等
4 = 较高
5 = 极高
```

### 5.1 时效性 `timeliness`

时效性回答：

> 这条信息是否新鲜，以及它是否具有明显的时间敏感性？

| 分数 | 锚点 |
|------|------|
| `1` | 已经过时，或主要是历史回顾；当前没有明显时间敏感性 |
| `2` | 信息较旧，仍有参考价值，但不需要及时关注 |
| `3` | 近期信息，仍处于有效窗口；适合正常阅读 |
| `4` | 较新且具有明显时间敏感性；越早知道越有价值 |
| `5` | 刚刚发生、首次披露或正在快速演变；延迟获取会明显降低价值 |

LLM 综合考虑：

```text
原始发布时间
当前时间
是否首次披露
是否属于持续演变中的事件
是否只是旧内容的重复转述
信息价值是否随时间快速衰减
```

### 5.2 影响力 `impact`

影响力回答：

> 如果这条信息成立，它可能影响多大范围，以及影响程度有多深？

影响力不等同于热度，也不等同于来源知名度。

| 分数 | 锚点 |
|------|------|
| `1` | 影响局限于很小范围，基本不改变外部判断 |
| `2` | 对单个产品、项目、团队或小范围用户有影响 |
| `3` | 对某个细分领域或一类用户有明显影响 |
| `4` | 对一个行业、较大用户群体或关键生态有明显影响 |
| `5` | 可能引发跨行业、市场级或长期结构性变化 |

LLM 综合考虑：

```text
受影响对象数量
影响范围
影响深度
影响持续时间
是否可能引发连锁变化
是否改变已有判断或决策
```

### 5.3 置信度 `confidence`

置信度回答：

> 这条信息本身有多可靠？

置信度判断事实可信程度，不判断信息是否重要。

| 分数 | 锚点 |
|------|------|
| `1` | 缺少可验证依据，来源不明，或存在明显矛盾 |
| `2` | 只有单一非官方来源，尚未获得独立验证 |
| `3` | 来源具有一定可信度，存在部分证据，但仍需要进一步确认 |
| `4` | 有较强证据支持，或多个可靠来源交叉印证 |
| `5` | 来自官方一手信息，或存在高度可验证的一手证据 |

LLM 综合考虑：

```text
是否是一手来源
来源角色
是否有原始链接或证据
是否有多个独立来源交叉验证
内容中是否存在不确定性措辞
是否存在明显冲突或无法验证的部分
```

约束：

```text
官方来源 ≠ 自动得到 5 分
KOL 来源 ≠ 自动低分
预印本论文 ≠ 自动得到 5 分
```

## 6. LLM 输入与输出

### 6.1 输入

LLM 获得：

```text
信息标题
信息正文
原始发布时间
当前处理时间
原始链接
Source 类型
Source 展示名称
Source 来源角色
Source 领域标签
Source 内容主题
Source 备注
```

LLM 不获得：

```text
Source 关注级别
空间权重
频道权重
场景分
```

原因：

- LLM 只负责判断信息本身。
- 场景权重由系统计算。
- Source 关注级别暂不参与计算，避免引入未经验证的人工偏差。

### 6.2 输出

```json
{
  "scoring_version": "content-dimensions-v1",
  "dimensions": {
    "timeliness": {
      "score": 5,
      "reason": "消息在 10 分钟内首次公开发布，具有明显时间敏感性。"
    },
    "impact": {
      "score": 4,
      "reason": "该发布可能影响 AI 模型市场和开发者生态。"
    },
    "confidence": {
      "score": 5,
      "reason": "信息来自公司官方账号，并提供了原始公告链接。"
    }
  }
}
```

输出约束：

```text
每个维度必须输出 1-5 的整数
每个维度必须输出一句简短理由
理由只能基于当前输入，不编造外部事实
信息不足时保守评分，并说明缺少什么
不输出场景分、权重、推送建议、日报建议或分流建议
```

## 7. 场景权重与场景分

### 7.1 场景分

同一条信息只有一份 LLM 维度分，但可以根据不同空间或频道的关注重点得到不同场景分。

公式：

```text
场景分 =
  时效性 × 时效性权重
  + 影响力 × 影响力权重
  + 置信度 × 置信度权重
```

约束：

```text
时效性权重 + 影响力权重 + 置信度权重 = 1
```

场景分范围：

```text
1-5
```

示例：

```text
维度分：
- 时效性：5
- 影响力：4
- 置信度：3

财经基础权重 v1：
- 时效性：0.5
- 影响力：0.3
- 置信度：0.2

财经场景分：
5 × 0.5 + 4 × 0.3 + 3 × 0.2 = 4.3
```

### 7.2 空间与频道

- 每个空间必须选择一套基础权重版本。
- 频道默认继承所属空间的基础权重版本。
- 频道允许选择另一套权重版本覆盖空间默认值。
- 页面展示场景分时保留一位小数，底层保留计算精度。

示例：

```text
财经空间
→ 财经基础权重 v1

财经 / 市场快讯
→ 财经高时效权重 v1

财经 / 宏观政策
→ 继承财经基础权重 v1
```

### 7.3 Source 关注级别

Source 关注级别保留：

```text
核心
常规
观察
```

但当前不定义乘数，不输出来源调整分，不参与场景分计算。

未来有真实数据支持后，可以再评估：

```text
来源调整分 = 场景分 × Source 关注系数
```

## 8. 权重方案与版本

### 8.1 两层结构

```text
权重方案
└── 权重版本
```

权重方案描述长期用途：

```text
AI 基础权重
财经基础权重
财经高时效权重
```

权重版本描述某个方案在某个时间点的具体参数：

```text
财经基础权重
├── v1：时效性 0.5 / 影响力 0.3 / 置信度 0.2
└── v2：时效性 0.4 / 影响力 0.4 / 置信度 0.2
```

空间和频道实际绑定具体版本。

### 8.2 权重版本状态

| 状态 | 是否允许编辑 | 是否允许新增使用 | 已有使用位置是否继续生效 | 是否允许删除 |
|------|--------------|------------------|--------------------------|--------------|
| 草稿 | 是 | 否 | 无 | 是 |
| 可用 | 否 | 是 | 是 | 否 |
| 已弃用 | 否 | 否 | 是 | 否 |
| 已归档 | 否 | 否 | 否 | 否 |

状态流转：

```text
草稿
→ 发布
→ 可用
→ 标记弃用
→ 已弃用
→ 所有空间和频道完成切换
→ 已归档
```

### 8.3 已弃用

已弃用表示停止新增使用，但不破坏已有配置。

```text
- 已有空间和频道继续正常计算
- 新空间和新频道不能选择已弃用版本
- 页面提示仍有哪些位置正在使用
- 用户明确切换到新版本
- 系统不自动切换
```

### 8.4 已归档

只有没有任何空间或频道继续使用时，权重版本才能归档。

归档后：

```text
- 不参与新信息计算
- 不允许新增使用
- 不允许删除
- 保留历史追溯
```

### 8.5 版本升级

```text
财经基础权重 v1
→ 复制为新草稿
→ 修改参数
→ 发布 v2
→ 将 v1 标记为已弃用
→ 用户逐步或批量切换空间和频道到 v2
→ v1 使用位置归零
→ 归档 v1
```

批量切换前必须展示受影响位置并二次确认。切换不自动重算历史新闻。

## 9. 评分记录

### 9.1 不覆盖历史

同一条信息每次评分都新增记录，不覆盖历史结果。

每条评分记录保存：

```text
评分方法版本
LLM 模型标识
评分时间
输入摘要或输入快照标识
Source 上下文快照
三个维度分数
三个维度理由
```

### 9.2 Source 上下文快照

每次评分时保存当时使用的 Source 上下文：

```json
{
  "source_type": "x_twitter",
  "source_display_name": "Example",
  "source_role": "kol",
  "domain_tags": ["AI"],
  "topic_tags": ["模型发布"]
}
```

这样即使后续修改 Source 标签，历史评分仍然可解释。

### 9.3 场景分记录

每条场景分记录保存：

```text
评分记录 ID
展示位置 ID
权重版本 ID
场景分
计算时间
```

切换权重版本后：

```text
- 新进入的信息使用新版本
- 历史场景分保留当时使用的权重版本
- 默认不重新计算历史新闻
```

## 10. 评分方法版本

评分方法版本与权重版本相互独立。

### 10.1 版本触发条件

以下内容发生变化时，创建新的评分方法版本：

```text
启用维度
维度定义
评分锚点
LLM 提示词
输出结构
```

例如：

```text
content-dimensions-v1
→ 时效性、影响力、置信度

content-dimensions-v2
→ 增加行动性
```

### 10.2 状态

| 状态 | 是否允许编辑 | 是否用于新信息评分 | 是否保留历史 |
|------|--------------|--------------------|--------------|
| 草稿 | 是 | 否 | 是 |
| 可用 | 否 | 可选择 | 是 |
| 当前使用 | 否 | 是 | 是 |
| 已归档 | 否 | 否 | 是 |

约束：

```text
同一时间只能有一个“当前使用”版本
已发布版本不可覆盖
切换版本时，新进入的信息使用新方法
历史评分默认不自动重评
```

## 11. 校准方向

### 11.1 分层抽样

未来调整锚点或权重时，从真实新闻中分层抽样：

```text
高分信息
中等分信息
低分信息
LLM 理由明显不合理的信息
同一事件的重复报道
同一新闻在不同空间中的场景分
Source 标签修改前后的样本
```

### 11.2 轻量人工反馈

未来可以提供：

```text
评分合理
评分偏高
评分偏低
维度判断不准确
LLM 理由不合理
```

反馈用于调整评分锚点、提示词和权重版本，不直接自动修改评分。

### 11.3 固定样例集

未来维护固定样例集，用于对比评分方法升级前后的变化：

```text
官方发布新模型
KOL 未经证实的爆料
一周前旧闻再次传播
开源项目一般版本更新
重大安全漏洞
财经政策突发调整
```

## 12. 待真实数据验证的问题

以下问题不在本轮定稿：

1. 置信度长期是否继续参与场景分，还是改为独立可靠性指标。
2. 是否需要场景相关度或场景化影响力。
3. 是否启用行动性。
4. 是否启用独特性。
5. Source 关注级别是否参与计算，以及使用什么系数。
6. 是否需要历史新闻批量重评。
7. 评分结果如何服务排序、筛选、日报、推送或自动分流。
