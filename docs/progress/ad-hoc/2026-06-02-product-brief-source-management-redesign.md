## 1. 背景

当前管理页已经具备频道空间切换、信息源卡片、内联添加、解绑和删除预览等基础能力，但信息源仍然偏向附属于某个空间的配置项。

后续平台需要同时管理 AI、财经等空间，持续积累 X/Twitter 与 RSS 信息源，并支持一个来源被多个位置复用。信息源还需要承载标签、健康状态、抓取配置和使用统计，为后续评分方法论与事件影响链分析提供基础。

本次重构将“信息源资产”和“内容展示位置”拆开：

```text
信息源 Source：它是谁、如何抓取、当前是否健康
展示位置：它获取的数据展示在哪个空间或频道
```

## 2. 产品目标

1. 建立独立的信息源库，统一管理 X/Twitter 和 RSS 来源。
2. 固定频道结构为两级：空间 → 频道；没有子频道。
3. 允许一个 Source 投放到多个空间或频道，但全局只抓取一次。
4. 通过 Source 标签沉淀人工筛选信息源时已经掌握的来源先验。
5. 让 Source 展示抓取状态、使用位置统计和异常信息。
6. 清空现有业务数据，以新的模型从空白状态重新录入，不做旧业务数据迁移。

## 3. 产品概念

### 3.1 空间与频道

频道结构固定为两级：

```text
空间
└── 频道
```

例如：

```text
AI
├── 模型动态
├── 行业资讯
└── 开源项目

财经
├── 宏观政策
├── 市场动态
└── 公司资讯
```

- 没有子频道。
- 不允许继续向下嵌套。
- 空间可以暂时没有频道。
- 同一空间内频道名称唯一，不同空间可以重名。
- 频道支持手动排序。

### 3.2 信息源 Source

Source 是平台统一管理的外部内容来源。

例如：

```text
OpenAI 官方 X：@OpenAI
OpenAI Blog RSS：https://example.com/rss.xml
```

Source 不属于频道结构。它负责维护：

- 来源身份。
- 标签和备注。
- 全局抓取策略。
- 验证状态和抓取状态。
- 使用位置统计。
- 来源身份变更历史。

### 3.3 展示位置

展示位置表示某个 Source 获取的数据应该展示在哪里。

展示位置可以是：

```text
空间根节点
或
空间下的具体频道
```

例如：

```text
OpenAI 官方 X
├── AI / 模型动态：启用
├── AI / 行业资讯：启用
└── 财经 / 公司资讯：暂停
```

页面中不使用技术术语 `Binding`。统一使用：

```text
展示位置
添加到空间
添加到频道
暂停接收
恢复接收
从当前位置移除
```

## 4. 页面信息架构

### 4.1 顶级导航

```text
浏览 | 管理 | 系统日志 | 告警
```

告警入口展示未处理数量。

### 4.2 管理页

管理页包含两个 Tab：

```text
空间管理 | 信息源库
```

#### 空间管理

页面使用两层 Tab，不展示树形目录：

```text
空间：
[ AI ] [ 财经 ]

频道：
[ 全部 ] [ 模型动态 ] [ 行业资讯 ] [ 开源项目 ]
```

- `全部` 是页面聚合入口，不是真实频道。
- 浏览页选择 `全部` 时，聚合空间根节点和全部频道新闻，并自动去重。
- 浏览页选择具体频道时，只展示该频道新闻。
- 管理页选择 `全部` 时，只管理直接投放到空间根节点的信息源。
- 管理页选择具体频道时，只管理投放到该频道的信息源。

#### 信息源库

信息源库使用表格作为主视图，默认展示全部 Source，包括未使用和待修复状态。

建议列：

| 信息源 | 类型 | 标签 | 运行状态 | 使用位置 | 最近抓取 | 历史新闻 | 操作 |
|--------|------|------|----------|----------|----------|----------|------|
| OpenAI 官方 X | X | AI · 官方 · 核心 | 抓取中 | 3 | 2 分钟前 | 328 | 查看 / 编辑 |

支持搜索：

```text
展示名称
来源身份
内容主题
备注
```

支持筛选：

```text
类型
运行状态
领域标签
来源角色
关注级别
使用空间
```

Source 提供独立详情页或右侧详情抽屉，具体交互形式由 UI（界面设计师）设计。

## 5. Source 录入与标签

### 5.1 通用字段

| 字段 | 是否必填 | 示例 | 说明 |
|------|----------|------|------|
| 类型 | 是 | X/Twitter | 创建后不可修改 |
| 来源身份 | 是 | @OpenAI | X 用户名或 RSS URL |
| 展示名称 | 是 | OpenAI 官方 X | 页面展示名称 |
| 领域标签 | 是 | AI、财经 | 固定选项，多选 |
| 来源角色 | 是 | 官方 | 固定选项，单选 |
| 内容主题 | 否 | 模型发布、研究动态 | 自由标签，多选 |
| 关注级别 | 是 | 核心 | 固定选项，单选 |
| 备注 | 否 | 重大产品发布优先关注 | 人工维护信息 |

领域标签首版固定选项：

```text
AI
财经
开源
科技
其他
```

来源角色首版固定选项：

```text
官方
媒体
KOL
社区
论文机构
其他
```

关注级别首版固定选项：

```text
核心
常规
观察
```

### 5.2 标签边界

v0.5 中标签用于：

- 信息源库展示。
- 搜索和筛选。
- 人工沉淀 Source 先验。
- 作为评分方法论草稿中的未来上下文。

v0.5 中标签不影响：

- 抓取频率。
- 抓取优先级。
- 入库规则。
- LLM 调用顺序。
- 单条新闻评分。
- 新闻状态流转。
- 自动推送。

### 5.3 X/Twitter Source

- 一个 X Source 只对应一个账号。
- 所有 X Source 共用一个 Filtered Stream 长连接。
- 收录原创推文和引用推文。
- 不收录回复和转推。

### 5.4 RSS Source

- 一条 RSS Feed 对应一个 Source。
- 一个网站有多个 Feed 时，分别创建多个 Source。

## 6. 创建与验证流程

### 6.1 创建入口

允许从两个入口新建 Source：

```text
信息源库 → 新建信息源
空间管理 → 添加信息源 → 搜索无结果 → 新建信息源
```

两个入口复用同一套创建表单。

### 6.2 验证

X/Twitter：

```text
输入用户名
→ 查询账号
→ 展示账号预览
→ 用户确认
→ 保存
```

RSS：

```text
输入 Feed URL
→ 请求并解析 Feed
→ 展示站点信息和最近文章预览
→ 用户确认
→ 保存
```

### 6.3 验证失败

验证失败的 Source 允许保存为“待修复”，但不允许添加到空间或频道，也不会开始抓取。

```text
验证失败
→ 保存为待修复
→ 修复来源身份
→ 重新验证成功
→ 允许添加展示位置
```

### 6.4 重复检查

| 类型 | 去重依据 |
|------|----------|
| X/Twitter | 标准化后的用户名，不区分大小写，不区分是否带 `@` |
| RSS | 标准化后的 Feed URL |

发现重复时，不创建新 Source，提示用户查看已有信息源或添加到当前位置。

### 6.5 来源身份修改

正常状态下不允许直接修改 X 用户名或 RSS URL。

以下状态允许修改来源身份：

```text
待修复
来源异常
```

修改后必须：

1. 重新检查重复来源。
2. 重新验证。
3. 验证成功后才允许恢复抓取。
4. 记录来源身份变更历史。
5. X Source 同步更新共享 Stream 规则。

## 7. 抓取与分发

### 7.1 全局抓取一次

同一个 Source 全局只抓取或监听一次，再将内容分发到全部启用的展示位置。

```text
请求或监听一次
→ 保存一份原始数据
→ 执行一次处理链路
→ 保存一份新闻
→ 关联到多个展示位置
```

### 7.2 抓取配置归属

| 配置项 | 归属 |
|--------|------|
| RSS 抓取周期 | Source |
| X 补偿抓取周期 | Source，默认 24 小时 |
| 单次最大抓取条数 | Source |
| 是否投放到某处 | 展示位置 |
| 某个位置是否接收新内容 | 展示位置 |

### 7.3 自动启停

Source 不提供独立的手工总开关。系统根据展示位置自动计算抓取状态：

```text
至少存在一个启用位置
→ Source 抓取中

全部位置暂停或移除
→ Source 停止抓取
```

### 7.4 X/Twitter 共享长连接

```text
XStreamManager
└── 一个共享长连接
    ├── @OpenAI：存在启用位置 → 保留监听规则
    ├── @AnthropicAI：存在启用位置 → 保留监听规则
    └── @Example：没有启用位置 → 不创建监听规则
```

首次启用位置时新增规则；暂停最后一个启用位置时移除规则；恢复任意位置时恢复规则。

## 8. 使用统计

信息源库和 Source 详情需要展示：

| 字段 | 说明 |
|------|------|
| 使用状态 | 使用中、未使用 |
| 抓取状态 | 抓取中、已停止、异常 |
| 展示位置总数 | 被添加到多少个空间或频道 |
| 启用位置数量 | 当前接收新内容的位置数量 |
| 暂停位置数量 | 当前暂停的位置数量 |
| 涉及空间数量 | Source 被多少个空间使用 |
| 最近成功抓取 | 最近一次成功时间 |
| 最近异常 | 最近失败原因摘要 |
| 连续失败次数 | 用于来源异常识别 |
| 累计历史新闻 | 已沉淀新闻数量 |

Source 详情列出具体展示位置：

| 空间 | 频道 | 状态 | 最近投放 | 操作 |
|------|------|------|----------|------|
| AI | 模型动态 | 启用 | 2 分钟前 | 暂停 / 移除 |
| 财经 | 公司资讯 | 暂停 | 3 天前 | 恢复 / 移除 |

## 9. 删除规则

### 9.1 删除 Source

删除全局 Source 时：

- 删除 Source。
- 删除全部展示位置。
- 停止抓取。
- 保留历史新闻。
- 历史新闻标记“来源已移除”。
- 删除前展示影响范围，并要求输入 Source 名称确认。

### 9.2 删除频道

删除频道时：

- 不删除 Source。
- 不删除历史新闻。
- 允许选择将展示位置迁移到空间根节点，或直接移除展示位置。
- 保留历史展示位置快照。

### 9.3 删除空间

删除空间时：

- 删除该空间下的频道。
- 删除该空间中的展示位置。
- 不删除全局 Source。
- 不删除历史新闻。
- 不影响 Source 在其他空间中的展示位置。
- 保留历史展示位置快照。
- 展示影响范围并要求输入空间名称确认。

## 10. 异常与告警

### 10.1 Source 状态

| 状态 | 含义 |
|------|------|
| 正常 | 验证通过，可以使用 |
| 待修复 | 创建时验证失败，不允许添加展示位置 |
| 来源异常 | 曾经正常，但后续持续失败 |
| 已停止 | 没有启用展示位置，不抓取 |
| 来源已移除 | Source 已删除，仅用于历史新闻展示 |

### 10.2 异常规则

```text
连续失败 1 至 2 次
→ 记录日志并自动重试

连续失败达到 3 次
→ Source 标记为来源异常
→ 生成告警
```

异常处理：

| 异常类型 | 处理 |
|----------|------|
| 临时网络错误、5xx | 指数退避重试 |
| 429 限流 | 按服务端提示或指数退避 |
| RSS 404、X 账号失效 | 暂停 Source，等待修复 |
| 401、403 鉴权失败 | 生成高优先级告警 |
| 单条内容解析失败 | 跳过当前内容，继续后续处理 |
| 系统内部错误 | 记录系统告警，不直接归因于 Source |

### 10.3 告警状态

```text
未处理
已确认
已恢复
已忽略
```

### 10.4 X Stream 全局异常

X Bearer Token 失效、共享长连接持续断开或规则同步失败时，生成一条 X Stream 全局告警，不为每个 X Source 重复生成相同告警。

## 11. 数据重置

Owner 已确认当前业务数据不需要迁移。

v0.5 实施时：

```text
旧业务数据全部清空
→ 不迁移
→ 不保留旧 API 兼容逻辑
→ 使用新模型从空白状态重新录入
```

清理范围：

```text
旧空间
旧频道或 sub_channels
旧 Source
旧展示位置
旧原始抓取记录
旧任务
旧新闻
旧告警
```

保留数据库 Schema、迁移机制、系统配置和环境变量。运行日志是否保留，由 DevOps 根据排障价值评估。

数据清理属于不可逆操作。实施阶段必须由 Architect 明确表级范围并 Review，DevOps 执行前输出数据量统计，由 Owner 确认后再执行。
